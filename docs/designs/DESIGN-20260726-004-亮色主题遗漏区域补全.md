# DESIGN-20260726-004：亮色主题遗漏区域补全

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：明亮模式经两次更改后仍有三处遗漏未响应主题：模式切换页签、配件下拉菜单、对话模式大部分内容
- **关联方案**：DESIGN-20260726-002（全站主题切换）、DESIGN-20260726-003（PC 端亮色色彩重构）
- **修订记录**：2026-07-26 二次调研后补充订阅/支付弹窗、context-choice-actions、collapsed 重复定义、pricing-template 系列等遗漏点

---

## 1. 背景

DESIGN-20260726-002 与 DESIGN-20260726-003 已分别建立亮色主题变量体系并替换了 PC 端约 30 处硬编码深色背景。但用户反馈经两次更改后，亮色模式下仍有三处明显未响应主题：

1. **配置/对话模式切换页签**：`.trae-mode-switch` 容器硬编码 `rgba(8,8,10,0.84)` 黑底 + `rgba(255,255,255,0.16)` 边框，按钮文字硬编码 `#858690`，激活态 `.mode-pill` 硬编码 `#fff` 白底 + `#050505` 黑字。亮色下整个页签仍是黑底，与周围浅色环境割裂。
2. **配件选择下拉菜单**：`.parts-dropdown-inner` 硬编码 `rgba(16,16,18,0.94)` 黑底 + `#27272f` 边框，亮色下展开后仍是黑底。
3. **对话模式大部分内容**：经全面排查，Chat 模式核心 UI（第 8575-9340 行密集区域）几乎全部使用 `#18181b`/`#242427`/`#27272a` 深色背景与 `#fff`/`#f4f4f5`/`#d4d4d8` 浅色文字，无任何 CSS 变量包裹，涉及侧边栏、历史列表、空状态粒子、对话气泡、输入 composer、prompt 下拉等约 60 处硬编码。尽管 `.chat-mode-shell`/`.chat-workspace`/`.chat-bg` 容器层已响应主题，但其内部子元素全部遗漏，导致亮色下对话模式仍呈深色。

二次调研另发现以下方案初版未覆盖的遗漏点（纳入本次方案一并修复）：
4. **订阅/支付弹窗（pricing-template 系列）**：`.pricing-template-card`、`.payment-template-modal`、`.pricing-plan-title`、`.pricing-template-card li/svg`、`.payment-template-options button` 等约 15 处硬编码 `#18181b` 底 + `#fff` 字 + `#27272a` 边框（第 11393-11549 行、第 12299-12302 行），亮色下订阅弹窗仍为全黑。
5. **context-choice-actions 选择按钮**：`.context-choice-actions button.selected` 硬编码 `#f4f4f5` 底 + `#08080a` 字（第 12033-12037 行），亮色下需反转。
6. **collapsed 重复定义**：`.chat-history-sidebar.collapsed` 第 11070 行重复硬编码 `#18181b`，需与主定义同步替换。

本次方案针对以上六处遗漏区域做补全修复，使亮色主题在 PC 端达到完整覆盖。

## 2. 功能描述

### 核心用户故事

作为用户，当我切换到明亮主题时，配置/对话模式切换页签、配件选择下拉菜单、对话模式的侧边栏/历史列表/对话气泡/输入框、订阅支付弹窗、上下文选择按钮等全部内容应随主题切换为浅色调，不再残留黑色背景与不协调的浅色文字。

### 功能输入输出与预期行为

- **入口**：复用现有主题切换按钮，无需新增。
- **视觉生效范围**：六处遗漏区域在亮色下立即响应。
  - 模式切换页签：容器底色为浅色半透明，按钮文字为深色，激活态 pill 为深色底浅色字。
  - 配件下拉菜单：展开后面板为白色/浅灰底，深色文字，浅色边框。
  - 对话模式：侧边栏浅色底深色字，历史列表浅色，空状态粒子可见，对话气泡浅色底，输入框浅色底深色字。
  - 订阅/支付弹窗：卡片白底深色字，边框浅灰，按钮保留品牌蓝色但 disabled 态适配亮色。
  - context-choice-actions：选中态反转为深底浅字。
- **暗色零回归**：所有变更仅作用于 `[data-theme="light"]` 作用域或替换为双向变量，暗色 `:root` 表现不变。

### 非功能性需求

- **零新依赖**：纯 CSS 变量与选择器覆盖。
- **不影响移动端**：移动端有独立覆盖体系（`--m-*` 变量），本次仅处理 PC 端选择器。
- **性能**：纯 CSS 切换，无重渲染。

## 3. 技术实现思路

### 整体策略

按区域分块处理，优先采用"直接替换为 CSS 变量"（保证暗亮双主题自动响应），对无法直接替换的渐变/特殊效果新增 `[data-theme="light"]` 覆盖规则。

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 对话模式硬编码数量多（约 60 处），替换过程遗漏 | 高 | 高 | 按 3.3 节 9 个子区域逐区替换并验收；利用调研清单逐项核对 |
| `.particle-orb` 亮色下粒子反转后视觉效果不佳（深色粒子在浅底上过重） | 中 | 中 | 提供深色粒子参数，实施时在浏览器实时调参（透明度/大小/阴影） |
| 用户气泡与助手气泡在亮色下区分度不足 | 中 | 低 | 用户气泡用 `var(--surface)`（纯白），助手气泡用 `var(--surface-2)`（浅灰）形成层次 |
| `.chat-composer` 渐变与阴影亮色覆盖后立体感丢失 | 中 | 低 | 亮色覆盖时保留轻微阴影 `var(--shadow)` 维持浮层感 |
| 变量替换在暗色下表现意外变化 | 低 | 中 | 替换时确认 `:root`（暗色）对应变量有取值；实施后切换暗色逐项验证 |
| `.chat-history-sidebar.collapsed` 重复硬编码遗漏 | 中 | 低 | 实施时全局搜索 `#18181b` 确认所有出现处同步替换（第 8666、11070、11399、11495、12301 行） |
| 订阅弹窗品牌蓝按钮在亮色下对比不足 | 低 | 低 | 保留 `#3867e8` 品牌蓝，亮色下蓝底白字仍清晰；仅 disabled 态适配 |
| pricing-template 系列选择器在 subscribe-modal 上下文中有重复定义 | 中 | 低 | 实施时注意选择器优先级，亮色覆盖规则需与原定义同级或更高 |
