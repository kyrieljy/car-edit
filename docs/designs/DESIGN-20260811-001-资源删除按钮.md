# DESIGN-20260811-001：资源（配件）删除按钮与删除能力

## 元信息
- **创建日期**：2026-08-11
- **状态**：待审核
- **关联需求**：给资源库「配件管理」中的配件行添加删除按钮，按钮位于"停用"下方、红色背景；点击后弹窗提示"删除后将无法恢复"，确认后执行删除。

---

## 1. 背景

当前管理员后台「资源库 → 配件管理」中，单个配件（part_assets）只能"编辑"和"停用/启用"，**没有任何删除入口**：前端 `AssetRow` 无删除按钮、API 无 `DELETE` 路由、数据库无 `deleteAsset` 函数。这与类型（category）、品牌（brand）已具备的删除能力不一致。

业务上管理员需要能清理无效/错误的配件资源（此前只能"停用"软隐藏，记录永久残留）。本次需求补齐配件的删除能力，并明确 UI 形态（红色删除按钮置于停用下方）与确认交互（原生弹窗 + "删除后将无法恢复"）。

经需求澄清，删除采用**引用保护策略**（与类型/品牌一致）：被外部实时引用时拒绝删除；无引用时硬删（不可恢复）。确认弹窗复用现有 `window.confirm` 原生弹窗风格。

## 2. 功能描述

- 在「配件管理」列表每个配件行（`AssetRow`）的操作区，于"停用/启用"按钮**下方**新增一个**红色背景**的"删除"按钮。
- 点击"删除"按钮：
  1. 先由前端调用 `window.confirm("删除后将无法恢复")`。
  2. 用户确认 → 发起 `DELETE /api/admin/assets/[id]`。
  3. 服务端 `deleteAsset(id)` 执行引用检查：
     - 若配件被**组合预设**（`prompt_templates.asset_id`）引用 → 拒绝删除，返回错误，前端提示"该配件被组合预设引用，请先解除后删除"。配件保留。
     - 若无外部实时引用 → 级联删除该配件自身的参考图（`part_asset_references`），再删除 `part_assets` 记录，写审计日志。
  4. 删除成功后刷新列表（该配件从列表消失）。
- 历史生成记录（`generation_jobs`）以 JSON 存储配件选择，无外键、属不可变历史留痕，按设计**不阻止删除**（详见风险章节）。
- 非功能性：按钮样式需在临床主题（`.admin-clinical`）下依旧为红色背景，不被既有 `.admin-clinical .admin-asset-row button` 覆盖规则吞掉。

## 3. 技术实现思路

整体分三层补齐删除链路，不新增表/字段：

1. **数据层（lib/server/db.ts）**：新增 `deleteAsset(id)`：
   - 统计 `prompt_templates` 中 `asset_id = ?` 的行数（外部实时引用）。
   - 若计数 > 0 → 抛错（HTTP 400），阻止删除。
   - 否则：`DELETE FROM part_asset_references WHERE asset_id = ?`（级联清理自身参考图）→ `DELETE FROM part_assets WHERE id = ?` → `writeAudit("", "admin.asset.delete", { id })`。
   - 与既有 `deleteBrand`/`deleteCategory` 的保护风格保持一致（有引用则阻止）。

2. **接口层（app/api/admin/assets/[id]/route.ts）**：在现有 `PATCH` 之外新增 `DELETE` 处理器：
   - `requireAdminUser()` 鉴权。
   - 调用 `deleteAsset(context.params.id)`，成功返回 `{ ok: true }`。
   - 异常走 `authErrorResponse`（引用冲突等返回 400）。

3. **前端层（components/admin-console.tsx + app/globals.css）**：
   - `AssetRow` 操作区（`.admin-asset-actions`）由横向改为纵向排列：编辑（上）→ 停用/启用（中）→ 删除（红，下），满足"放在停用下方"。
   - 新增 `removeAssetItem(asset)`：先 `window.confirm("删除后将无法恢复")`，确认后 `fetch(DELETE)`，成功 `onChanged()` 刷新，失败用 `readError` 提示服务端返回信息（如引用冲突）。
   - `globals.css`：新增 `.admin-asset-actions button.delete-asset { background: var(--red); color: #fff; ... }`；并在 `.admin-clinical` 作用域下用更高优先级（如 `.admin-clinical .admin-asset-actions button.delete-asset`，置于文件靠后）覆盖背景/文字，避免被 `.admin-clinical .admin-asset-row button` 规则染色（参考此前 StyledSelect 触发按钮被临床主题覆盖的坑）。

### 模块影响
- **前台工作室（配置模式选配件）**：`getCatalog()` 已过滤 `asset.active`，删除的是 `active` 或无引用的配件；被删除配件不再出现在目录，不影响现存正常配件。低风。
- **组合预设（prompt_templates）**：被引用时阻止删除，保证预设不悬空。中收益、低风。
- **生成历史（generation_jobs）**：历史记录 JSON 中含已删配件选择，无外键、不可变，仅显示层面可能残留旧名称（不影响重新生成，因从目录取件）。低风。
- **审计（audit_logs）**：删除动作写入审计，便于追溯。正向。

| 风险 | 可能性（高/中/低） | 影响（高/中/低） | 应对措施 |

| 历史生成记录引用的配件被删导致留痕失效 | 低 | 中 | 明确设计决策：历史生成记录按"不可变留痕"处理，不阻止删除；若后续业务要求阻止，需对 `generation_jobs.selections_json` 做 JSON 扫描（本次不实现，记入待确认） |
| 删除后仍被其它缓存/索引引用 | 低 | 低 | 删除后 `onChanged()` 刷新管理台列表；前台目录走 `getCatalog()` 实时过滤，无独立缓存 |
