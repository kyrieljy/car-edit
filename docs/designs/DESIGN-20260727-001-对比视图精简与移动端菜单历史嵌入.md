# DESIGN-20260727-001：对比视图精简与移动端菜单历史嵌入

## 元信息
- **创建日期**：2026-07-27
- **状态**：待审核
- **关联需求**：改图界面去掉原图/生成图页签仅保留对比；移动端去掉历史按钮将会话列表嵌入左上角菜单抽屉；移动端对比图片尺寸完全一致

---

## 1. 背景

当前改图界面（PC 端 `ResultPanel` 与移动端 `MobileConfigMode`）有三个视图页签：原图、生成图、对比。用户在实际使用中几乎只关注"对比"视图——通过滑块对比改装前后效果。原图和生成图的单独展示属冗余入口，增加了交互复杂度。同时，三个页签占据界面空间，对移动端尤为拥挤。

移动端方面，对话模式（chat mode）当前在 `MobileScreenHead` 区域内嵌了一个 `mobile-chat-sidebar-toggle` 按钮（Menu 图标）用于打开 `ChatHistorySidebar`。该按钮与左上角全局菜单按钮（`mobile-floating-menu`）功能重叠且位置接近，用户容易混淆。DESIGN-20260725-003 已将左上角菜单按钮统一为打开 `MobileMenuDrawer`（展示四个功能子菜单），但历史会话入口仍散落在对话模式内部。

此外，移动端对比滑块中两张图片使用 `object-fit: contain`，当原图与生成图宽高比不同时，两图在容器内的可见区域大小不一致，影响对比预览效果。

本次需求将：
1. 精简改图界面，仅保留对比视图。
2. 将移动端对话历史会话列表直接嵌入左上角菜单抽屉页面。
3. 确保移动端对比滑块中两张图片尺寸完全一致。

## 2. 功能描述

### 2.1 改图界面精简（PC + 移动端）

- **移除内容**：去掉"原图"和"生成图"两个页签按钮及其对应的独立展示内容；移除整个三按钮 `view-switch` / `mobile-view-tabs` 切换栏。
- **保留内容**：仅保留"对比"视图的内容（即 `ImageComparisonSlider` 组件及其交互）。
- **显示逻辑**：
  - 当有生成结果图时：始终展示对比滑块（原图与生成图重叠对比）。
  - 当有上传原图但无生成结果时：显示空状态占位（提示用户点击生成），不再展示原图本身。
  - 当无上传原图时：保持现有的上传引导空状态（`result-empty` / `mobile-upload-empty`）。
- **导出行为**：保存/导出按钮始终下载生成图（与当前对比模式导出行为一致），`saveResult` 调用统一传 `"compare"`。
- **自动播放**：对比滑块在新生成结果出现时自动重新挂载并播放动画（通过 `compareKey` 递增触发）。

### 2.2 移动端菜单抽屉嵌入历史会话

- **移除入口**：移除 `MobileChatMode` 中 `MobileScreenHead` 的 `leftAction`（`mobile-chat-sidebar-toggle` 按钮）。
- **菜单抽屉结构调整**：
  - 四个功能子菜单（改图、生图、视频、特效）由当前 2×2 网格布局改为**单列纵向排列**。
  - 当处于对话模式（`appMode === "chat"`）时，在四个子菜单**下方**继续展示聊天会话列表（置顶会话 + 最近会话），用户可直接点击会话进行切换。
  - 当处于配置模式（`appMode === "config"`）时，仅展示四个子菜单，不展示会话列表。
- **会话列表数据来源**：由 `ChatMode` 组件通过回调上报会话数据（`sessions` + `activeSessionId`），`MobileStudioApp` 统一存储并传递给 `MobileMenuDrawer` 渲染。
- **会话选择交互**：用户在菜单抽屉中点击某个会话后，关闭菜单抽屉并触发 `ChatMode` 加载该会话。
- **ChatHistorySidebar 处理**：移动端不再通过 `chatSidebarOpen` 触发 `ChatHistorySidebar` 的移动端抽屉。`ChatHistorySidebar` 组件保留在 `ChatMode` 中（PC 端仍使用桌面侧栏），但其 `mobileOpen` 在移动端恒为 `false`，不再渲染移动端全屏抽屉。

### 2.3 移动端对比图片尺寸一致

- **问题**：当前 `.compare-slider-layer` 使用 `object-fit: contain`，两张图在容器内按各自宽高比缩放，导致可见区域大小不一致。
- **方案**：在移动端（`.mobile-media-upload` 作用域内）将对比滑块图层的 `object-fit` 改为 `cover`，使两张图均填满容器，确保可见区域完全一致。
- **影响范围**：仅影响移动端对比滑块，PC 端对比滑块保持 `contain` 不变。

## 3. 技术实现思路

### 3.1 改图界面精简

#### 3.1.1 ViewMode 状态简化

- `ViewMode` 类型定义保留（`"generated" | "original" | "compare"`），避免大规模类型改动。
- `viewMode` 初始值由 `"generated"` 改为 `"compare"`。
- `setViewModeWithCompareReset` 函数保留，但不再从 UI 按钮调用。新增逻辑：当 `job` 状态变为 `"succeeded"` 时自动递增 `compareKey`（通过 `useEffect` 监听 `job?.status`），使对比滑块重新挂载并播放动画。

#### 3.1.2 PC 端 ResultPanel 改造

- 移除 `view-switch` div（含三个按钮）。
- 移除 `viewMode === "original"` 和 `viewMode === "generated"` 的条件渲染分支。
- 保留 `viewMode === "compare"` 分支：当 `vehiclePreview && hasGeneratedResult` 时渲染 `ImageComparisonSlider`。
- 新增空状态分支：当 `vehiclePreview` 存在但 `!hasGeneratedResult` 时，渲染空状态占位（复用 `result-empty` 样式，文案改为提示生成）。
- 当 `!vehiclePreview && !job` 时，保持现有 `result-empty` 上传引导。
- `showCompletedElapsed` 的条件由 `viewMode !== "original"` 简化为恒 `true`（因仅剩对比视图）。
- 导出按钮的 `saveResult` 调用简化为 `saveResult("compare")`。

#### 3.1.3 移动端 MobileConfigMode 改造

- 移除 `mobile-view-tabs` div（含三个按钮）。
- 移除 `effectiveViewMode` 相关的分支判断（`isCompareView`、`isGeneratedResultView`、`canUploadFromMedia` 等）。
- 图片展示逻辑简化为：
  - 有生成结果：渲染 `ImageComparisonSlider`。
  - 有原图但无生成结果：渲染空状态占位（新增，文案如"请生成改装效果"）。
  - 无原图：渲染 `mobile-upload-empty`（上传引导，保持现有行为）。
- `mediaCardClassName` 简化：移除 `is-compare`、`is-generated-result`、`can-toggle-chrome` 等基于视图模式的 class。当有生成结果时添加 `is-compare`（保留 chrome 隐藏功能）。
- `mobile-media-upload` 按钮的 `onClick` 逻辑简化：有生成结果时切换 chrome 显示/隐藏；无生成结果时触发上传。
- 导出按钮的 `saveResult` 调用简化为 `saveResult("compare")`。

### 3.2 移动端菜单抽屉嵌入历史会话

#### 3.2.1 ChatMode 会话数据上报

- 在 `ChatModeProps` 中新增可选回调：`onSessionsChange?: (sessions: ChatSession[], activeSessionId: string) => void`。
- 在 `ChatMode` 内通过 `useEffect` 监听 `sessions` 和 `activeSessionId` 变化，调用 `onSessionsChange` 上报最新会话列表与当前活跃会话 ID。
- 此回调仅在 `mobileVariant` 为 `true` 时触发（PC 端无需上报）。

#### 3.2.2 会话选择指令传递

- 在 `ChatModeProps` 中新增可选属性：`pendingSessionId?: string | null` 和 `onPendingSessionConsumed?: () => void`。
- `ChatMode` 内通过 `useEffect` 监听 `pendingSessionId`：当值非空时调用内部 `selectSession(id)`，随后调用 `onPendingSessionConsumed()` 清除待处理标记。
- `selectSession` 内部已有的 `if (mobileSidebarOpen) setMobileSidebarOpen(false)` 逻辑不影响（`mobileSidebarOpen` 在移动端恒为 `false`）。

#### 3.2.3 MobileStudioApp 状态管理

- 新增状态：`chatSessions: ChatSession[]`（初始空数组）、`chatActiveSessionId: string`（初始空串）、`pendingChatSessionId: string | null`（初始 `null`）。
- `onSessionsChange` 回调赋值给 `chatSessions` 和 `chatActiveSessionId`。
- 新增 `handleSelectChatSession(id: string)` 函数：设置 `pendingChatSessionId = id`，同时 `setMenuDrawerOpen(false)` 关闭菜单抽屉。
- 将 `pendingChatSessionId` 和 `onPendingSessionConsumed`（清空 `pendingChatSessionId`）传递给 `MobileChatMode` → `ChatMode`。

#### 3.2.4 MobileMenuDrawer 改造

- **布局变更**：`.mobile-menu-grid` 由 `grid-template-columns: 1fr 1fr`（2×2）改为 `grid-template-columns: 1fr`（单列）。菜单卡片样式调整为横向布局（图标在左、文字在右）以适应单列。
- **新增 Props**：`appMode: AppState`、`chatSessions: ChatSession[]`、`chatActiveSessionId: string`、`onSelectChatSession: (id: string) => void`、`language: Language`。
- **会话列表渲染**：当 `appMode === "chat"` 时，在四个子菜单下方渲染会话列表区域：
  - 分"置顶会话"和"最近会话"两个分组（复用 `ChatSession` 类型的 `pinned` 字段分组）。
  - 每个会话条目显示标题、预览文本、活跃状态高亮。
  - 点击会话条目调用 `onSelectChatSession(session.id)`。
  - 空列表时显示空状态文案（如"暂无历史会话"）。
- **会话列表样式**：新增 `.mobile-menu-chat-list`、`.mobile-menu-chat-section`、`.mobile-menu-chat-item` 等 CSS 类，使用设计令牌（`--text`、`--muted`、`--surface`、`--line-soft`、`--yellow`）适配主题。

#### 3.2.5 MobileChatMode 改造

- 移除 `MobileScreenHead` 的 `leftAction`（`mobile-chat-sidebar-toggle` 按钮）。
- `MobileScreenHead` 仅保留标题和语言切换。
- `ChatMode` 的 `mobileSidebarOpen` 保持传递（值为 `chatSidebarOpen`，恒为 `false`），`setMobileSidebarOpen` 保持传递但不再被触发。
- 新增传递 `pendingSessionId` 和 `onPendingSessionConsumed` 给 `ChatMode`。
- 新增传递 `onSessionsChange` 给 `ChatMode`。

### 3.3 移动端对比图片尺寸一致

- 在 `app/globals.css` 中，为移动端对比滑块图层添加 `object-fit: cover` 覆盖规则。
- 选择器：`.mobile-media-upload .compare-slider-layer { object-fit: cover; }`。
- 该规则仅在 `.mobile-media-upload` 作用域内生效（移动端独有），不影响 PC 端 `.result-window` 中的对比滑块。
- `object-fit: cover` 确保两张图均填满容器，裁剪方向由 `object-position: center`（默认值）控制，保证车辆主体居中可见。

## 6. 风险与应对

| 风险 | 可能性（高/中/低） | 影响（高/中/低） | 应对措施 |
|------|--------------------|--------------------|----------|
| 移除原图/生成图页签后，用户无法单独查看原图或生成图 | 中 | 中 | 对比滑块拖至最左/最右即可全显原图/生成图，功能等价；导出始终下载生成图 |
