# DESIGN-20260726-006：改图对比简化与弹窗主题适配及移动菜单重构

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：1.改图界面去掉原图/生成图文签只保留对比；2.PC端会员/个人中心弹窗明暗主题适配；3.移动端历史会话移入左上角菜单

---

## 1. 背景

当前产品存在三个独立的体验问题：

1. **改图界面页签冗余**：PC 端 `car-mod-studio.tsx` 与移动端 `mobile-studio-app.tsx` 的改图结果区均包含「原图 / 生成图 / 对比」三个页签。用户核心诉求是查看改装前后对比，三个页签增加了操作步骤。此前 DESIGN-20260725-002、DESIGN-20260726-001 已多次迭代对比滑块本身，现需进一步简化为仅保留对比视图。

2. **PC 弹窗未跟随明暗主题**：DESIGN-20260726-003/004/005 已完成 PC 端亮色主题主体适配，但「个人中心」弹窗（`DesktopAccountPanel`）完全遗漏（约 30 处硬编码深色），「会员」弹窗（`SubscribeModal`）的最外层容器与遮罩仍为纯黑 `#000`，导致亮色模式下弹窗背景全黑。

3. **移动端历史会话入口位置不佳**：DESIGN-20260725-003 将历史会话入口放在 `MobileChatMode` 的 `MobileScreenHead` 左侧按钮中，用户反馈该入口不够直观，且与左上角菜单功能割裂。需将历史会话整合进左上角菜单抽屉，同时四个子菜单改为单列布局。

## 2. 功能描述

### 2.1 改图界面页签简化（PC + 移动端）

- **移除内容**：删除「原图」「生成图」「对比」三个页签切换按钮（`.view-switch` 容器）；删除「原图」和「生成图」两个渲染分支。
- **保留内容**：仅保留「对比」页签的渲染逻辑（`ImageComparisonSlider` 对比滑块），且不再需要页签条件守卫，直接渲染。
- **无生成图时的兜底**：当用户仅上传了原图但尚未生成结果时，对比区域显示空状态提示（复用现有 `.result-empty` 样式，文案调整为引导用户先执行生成），不再显示原图或生成预览作为兜底。
- **适用范围**：PC 端 `car-mod-studio.tsx` 的 `ResultPanel` 与移动端 `mobile-studio-app.tsx` 中相同的页签结构，两端同步修改。

### 2.2 PC 端会员/个人中心弹窗主题适配

- **个人中心弹窗**（`DesktopAccountPanel`，`.account-panel*` 系列）：为约 30 处硬编码深色背景/边框/文字新增 `[data-theme="light"]` 亮色覆盖规则，覆盖遮罩、主容器、头部、用户信息区、额度卡片、Tab 导航、表单输入框、头像选择器、消息提示等全部子区域。
- **会员弹窗**（`SubscribeModal`，`.pricing-template*` 系列）：补充最外层容器与遮罩的亮色覆盖——`.pricing-backdrop` 背景从 `#000` 改为亮色半透明遮罩；`.subscribe-modal.pricing-template` 背景从 `#000` 改为亮色卡片底；`.pricing-template-head h2`/`small` 文字色从 `#fff`/`#8b96a8` 改为亮色文字。子元素已在 DESIGN-004 适配，无需重复。
- **登录弹窗**（`AuthModal`）：本就是固定浅色设计，不处理。

### 2.3 移动端菜单重构与历史会话整合

- **删除历史会话按钮**：移除 `MobileChatMode` 中 `MobileScreenHead` 的 `leftAction`（`mobile-chat-sidebar-toggle` 按钮）。
- **四子菜单改单列**：`MobileMenuDrawer` 中 `.mobile-menu-grid` 从 2 列网格改为单列纵向排列。
- **历史会话整合进菜单**：在 `MobileMenuDrawer` 的四子菜单下方，当 `appMode === "chat"` 时，继续展示历史会话列表。
- **点击历史会话行为**：关闭菜单抽屉 → 切换到对话模式 → 加载选中的会话。

## 3. 技术实现思路

### 3.3 移动端菜单重构与历史会话整合

#### 删除历史会话按钮

- 移除 `MobileChatMode`（`mobile-studio-app.tsx` 第 3308-3317 行）中 `leftAction` 整段 JSX。
- `MobileScreenHead` 的 `leftAction` 为可选 prop，删除后头部左侧仅显示 eyebrow/title。
- 清理 `mobile-studio-app.tsx` 第 722 行附近 `MobileChatMode` 调用处对 `mobileSidebarOpen`/`setMobileSidebarOpen` 的传参（若不再需要独立触发 ChatHistorySidebar 抽屉）。
- 清理 CSS `.mobile-chat-sidebar-toggle` 相关规则（globals.css 第 7053-7070 行、第 2729 行）。

#### 四子菜单改单列

- 修改 `globals.css` 第 7008 行 `.mobile-menu-grid` 的 `grid-template-columns: 1fr 1fr` → `1fr`（单列）。
- 视觉微调：单列布局下卡片宽度变宽，可能需要调整 `.mobile-menu-card` 的内边距与布局（图标+文字的横向排列）。

#### 历史会话整合进 MobileMenuDrawer

**核心挑战**：`ChatHistorySidebar` 的会话数据（pinned/recent/activeSessionId/onSelect/onPin/onDelete 等）由 `ChatMode` 内部 hook 管理，`MobileMenuDrawer` 当前无法直接获取。

**实现策略——状态提升 + 组件复用**：

1. **提取会话数据到共享层**：将 `ChatMode` 内部的会话列表管理逻辑（获取会话列表、置顶、删除、新建、选中）提取为独立 hook（如 `useChatSessions`），或提升至 `MobileStudioApp`/`MobileChatMode` 顶层 state。
2. **ChatMode 改为消费外部数据**：`ChatMode` 接收会话数据与操作回调作为 props，不再内部管理（保持 PC 端 ChatMode 不受影响——PC 端继续内部管理，移动端通过 props 注入）。
3. **MobileMenuDrawer 扩展 props**：
   - 新增 `appMode: AppMode` —— 判断是否为对话模式。
   - 新增会话数据 props：`chatSessions`（pinned + recent 列表）、`activeSessionId`、`onSelectSession`、`onNewChat`、`onPinSession`、`onDeleteSession` 等。
   - 或直接传入 `chatHistorySlot`（ReactNode），由父组件决定渲染内容。
4. **MobileMenuDrawer 内渲染**：当 `appMode === "chat"` 时，在 `.mobile-menu-grid` 下方追加历史会话区块，复用 `ChatHistorySidebar` 组件（以 `mobileOpen=false`、`effectiveCollapsed=false` 的内联模式渲染，不显示遮罩与抽屉动画），或渲染精简版会话列表。
5. **点击会话行为**：`onSelectSession` 回调执行：`setMenuDrawerOpen(false)` → 确保 `appMode === "chat"` → 调用 `onSelect(sessionId)` 加载会话。

**备选方案（若状态提升改动过大）**：在 `MobileMenuDrawer` 中渲染一个「历史会话」入口按钮，点击后调用 `setChatSidebarOpen(true)` 触发现有 `ChatHistorySidebar` 抽屉覆盖在菜单之上。但此方案不满足"在菜单内继续展示历史会话"的需求，仅作为降级备选。

#### MobileMenuDrawer 调用处修改

主组件 `MobileStudioApp` 第 728-736 行 `MobileMenuDrawer` 调用处，新增 `appMode` prop 及会话数据 props 的传递。
