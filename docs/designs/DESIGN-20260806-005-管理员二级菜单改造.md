# DESIGN-20260806-005：管理员二级菜单改造

## 元信息
- **创建日期**：2026-08-06
- **状态**：已实施
- **关联需求**：将管理员界面的一级平铺菜单列表改造成"按业务职能分类"的二级菜单结构

---

## 1. 背景

管理员后台（`components/admin-console.tsx`）侧边栏当前有 23 个一级菜单项（`generationNavItems` 数组），以平铺方式渲染在 `aside.admin-sidebar` 的 `<nav>` 中。随着功能迭代，菜单数量已增长到 23 个，平铺列表过长，管理员需要滚动才能找到目标入口，且无法从结构上感知功能归属。

本次需求将菜单按"业务职能"维度分为 5 个一级分组，形成二级菜单结构，提升导航效率和可读性。

### 用户确认的设计决策

| 决策项 | 确认结果 |
|--------|----------|
| 数据看板定位 | **独立置顶** — 不归入任何分组，单独放在侧边栏顶部作为快捷入口 |
| 分组默认展开状态 | **手风琴模式** — 仅展开当前活跃菜单所在的分组，切换到其他组时自动折叠前一组 |
| 顶部面包屑 | **保持现状** — 面包屑仍只显示当前菜单标题，不显示分组名 |
| 精简模式（104px） | **仅显示图标** — 折叠模式下隐藏分组标题，所有菜单图标平铺排列 |

## 2. 功能描述

### 2.1 菜单分组结构

数据看板独立置顶，其余 22 个菜单分入 5 个一级分组：

| 分组名称 | 子菜单 | 数量 |
|----------|--------|------|
| 系统配置 | 资源库、头像预设、模型 API、提示词、Workflow、风控 SOP | 6 |
| 商业运营 | 会员配置、成本查看、订单 | 3 |
| 用户与安全 | 用户管理、用户画像、审计日志 | 3 |
| 数据分析 | 生成记录、用户分析、失败分析、订单分析、额度监控、系统健康、质量分析、失败样本 | 8 |
| 运维工具 | 消息推送、报表导出 | 2 |

**合计**：1（独立置顶）+ 6 + 3 + 3 + 8 + 2 = 23 ✓

### 2.2 交互行为

1. **独立置顶项**：数据看板作为独立按钮渲染在分组列表上方，与分组之间有视觉分隔。
2. **手风琴展开**：页面加载时，自动展开当前活跃 `tab` 所属的分组，其余分组折叠。点击其他分组标题时，前一组自动折叠，新组展开。点击分组内的子菜单切换 `tab` 时，不改变展开状态（仅切换高亮）。
3. **分组标题样式**：分组标题显示分组名称和子菜单数量（如"系统配置 · 6"），点击可展开/折叠。展开时标题右侧的 chevron 图标旋转 90°。
4. **精简模式**：侧边栏折叠到 104px 时（`.sidebar-collapsed`），隐藏分组标题和子菜单文字，所有菜单图标平铺排列，行为与当前一致。

### 2.3 非功能需求

- 不影响现有 `AdminTab` 类型定义、`openTab()` 函数、面板条件渲染逻辑。
- 不影响用户端界面和 API。
- 不影响提示词生成流程。
- 新增 CSS 样式限定在管理后台侧边栏作用域内。

## 3. 技术实现思路

### 3.1 数据结构改造

将现有的扁平数组 `generationNavItems: Array<{ id, label, sub, icon }>` 改造为分组结构：

```
新增类型 NavGroup = {
  id: string              // 分组标识，如 "system-config"
  label: string           // 分组中文名，如 "系统配置"
  icon: React.ReactNode   // 分组图标
  items: NavItem[]        // 该分组下的菜单项数组（复用现有 NavItem 结构）
}

改造后结构：
- dashboardItem: NavItem          // 数据看板独立项（从 generationNavItems 中提取）
- navGroups: NavGroup[]          // 5 个分组，每组包含 items 数组
```

原有的 `navItems`（旧版 9 项简版）和 `generationNavItems`（23 项完整版）合并为统一的数据源：1 个独立项 + 5 个分组。每个 `NavItem` 的 `{ id, label, sub, icon }` 结构不变。

### 3.2 状态管理

新增一个状态 `expandedGroupId: string | null`，记录当前展开的分组 ID。

- **初始化**：根据当前 `tab` 值，查找其所属的分组 ID 并设为 `expandedGroupId`。若 `tab` 为 `dashboard`（独立项），则 `expandedGroupId` 默认为第一个分组。
- **点击分组标题**：设置 `expandedGroupId` 为被点击的分组 ID（手风琴：同时关闭其他分组）。
- **切换 tab（`openTab`）**：调用现有 `openTab(tabId)` 逻辑，同时更新 `expandedGroupId` 为新 tab 所属的分组 ID（若 tab 为 dashboard 则不改变展开状态）。

需要一个辅助函数 `findGroupIdByTab(tab: AdminTab): string | null`，遍历 `navGroups` 查找 tab 所属的分组。

### 3.3 侧边栏渲染改造

当前渲染逻辑（`components/admin-console.tsx` 第 391-401 行）：

```
<nav>
  {generationNavItems.map((item) => (
    <button>...</button>
  ))}
</nav>
```

改造后渲染逻辑：

```
<nav>
  {/* 1. 独立置顶：数据看板 */}
  <button class={tab === "dashboard" ? "selected" : ""}>...</button>

  {/* 2. 分隔线 */}
  <div class="nav-divider" />

  {/* 3. 分组列表 */}
  {navGroups.map((group) => (
    <div class="nav-group">
      {/* 分组标题（可点击展开/折叠） */}
      <button class="nav-group-header" onClick={() => toggleGroup(group.id)}>
        <span class="nav-group-icon">{group.icon}</span>
        <span class="nav-group-label">{group.label}</span>
        <span class="nav-group-count">{group.items.length}</span>
        <ChevronDown class="nav-group-chevron" data-expanded={expandedGroupId === group.id} />
      </button>
      {/* 子菜单（展开时显示） */}
      {expandedGroupId === group.id && (
        <div class="nav-group-items">
          {group.items.map((item) => (
            <button class={tab === item.id ? "selected" : ""} onClick={() => openTab(item.id)}>
              <span class="nav-glyph">{item.icon}</span>
              <span class="nav-copy">
                <strong>{item.label}</strong>
                <em>{item.sub}</em>
              </span>
            </button>
          ))}
        </div>
      )}
    </div>
  ))}
</nav>
```

子菜单按钮复用现有的 `.nav-glyph` / `.nav-copy` / `.selected` 样式类，保持视觉一致性。

### 3.4 精简模式适配

现有精简模式通过 `.admin-optimus.sidebar-collapsed` 控制侧边栏宽度为 104px 并隐藏 `.nav-copy`。

改造后需额外处理：
- 在 `.sidebar-collapsed` 状态下，隐藏 `.nav-group-header`（分组标题）和 `.nav-divider`（分隔线）。
- 在 `.sidebar-collapsed` 状态下，将 `.nav-group-items` 的 `display` 从条件渲染改为始终显示（但仅图标），因为折叠模式下所有图标需平铺。
- 折叠模式下，子菜单按钮复用现有 `.nav-glyph` 样式（仅图标，文字已通过 `.nav-copy` 的 `width: 0; opacity: 0` 隐藏）。

实现方式：在折叠状态下，通过 CSS 让 `.nav-group-header` 隐藏、`.nav-group-items` 始终展开（`display: contents` 或 `display: grid`），使得所有子菜单图标平铺。

### 3.5 openTab 函数增强

当前 `openTab` 函数仅设置 `view.tab`：

```
const openTab = (t: AdminTab) => {
  setView({ type: "tab", tab: t })
}
```

改造后增加分组自动展开逻辑：

```
const openTab = (t: AdminTab) => {
  setView({ type: "tab", tab: t })
  const groupId = findGroupIdByTab(t)
  if (groupId) setExpandedGroupId(groupId)
}
```

### 3.6 初始化逻辑

组件初始化时，`expandedGroupId` 的默认值需要根据初始 tab 设置：

```
const [expandedGroupId, setExpandedGroupId] = useState<string | null>(
  findGroupIdByTab(view.type === "tab" ? view.tab : "dashboard")
)
```

若初始 tab 为 `dashboard`（独立项），`findGroupIdByTab` 返回 `null`，此时默认展开第一个分组 `navGroups[0].id`。

## 7. 实施步骤

1. **数据结构改造**：在 `admin-console.tsx` 中定义 `NavGroup` 类型，将 `generationNavItems` 拆分为 `dashboardItem`（独立项）和 `navGroups`（5 个分组的数组），每个分组的 `items` 复用原 `NavItem` 结构。保留原 `navItems`（旧版 9 项）如无其他引用则删除。

2. **状态与函数新增**：新增 `expandedGroupId` 状态、`findGroupIdByTab` 辅助函数、`toggleGroup` 函数。增强 `openTab` 函数，在切换 tab 时自动更新 `expandedGroupId`。

3. **侧边栏渲染改造**：重写 `<nav>` 内部渲染逻辑，渲染"独立置顶项 + 分隔线 + 分组列表（标题可点击 + 子菜单条件展开）"。子菜单按钮复用现有样式类。

4. **CSS 样式新增**：在 `app/globals.css` 的管理后台侧边栏样式区域（约第 6617 行附近）新增分组相关样式类。在精简模式样式区域（约第 7875 行附近）新增折叠模式下的分组隐藏与图标平铺样式。

5. **验证与核对**：启动开发服务器，逐一点击 23 个菜单确认路由正确、面板渲染正确；测试手风琴展开/折叠行为；测试精简模式下图标平铺；测试从详情页返回时分组定位是否正确。
