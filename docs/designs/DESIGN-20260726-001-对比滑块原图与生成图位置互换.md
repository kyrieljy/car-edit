# DESIGN-20260726-001：对比滑块原图与生成图位置互换

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：改图菜单配置模式对比部分，交换原图与生成图位置，使从左向右滑动由原图变为生成图，其它内容不变

---

## 1. 背景

配置模式的"对比"视图使用 `ImageComparisonSlider` 组件对原图与生成图进行重叠对比。当前实现中，原图（`beforeSrc`）作为顶层被裁剪到分隔线左侧，生成图（`afterSrc`）作为底层铺满容器并在分隔线右侧显露。这导致从左向右拖动滑块时，画面是从生成图过渡到原图，与用户"从原图过渡到生成图"的自然预期相反。用户希望交换两图位置，使从左向右滑动时呈现"原图 → 生成图"的过渡效果。

## 2. 功能描述

- **核心用例**：用户在配置模式生成结果后切换到"对比"视图，从左向右拖动对比滑块（或自动播放），画面应从原图逐步过渡为生成图。
- **输入/输出**：
  - 输入：原图 URL（`vehiclePreview`）、生成图 URL（`resultImageUrl`）、滑块位置百分比。
  - 输出：分隔线左侧显示生成图、右侧显示原图；滑块位于最左端时全显原图，位于最右端时全显生成图。
- **行为变更**：
  - position 0%（分隔线最左）：原图全显（当前为生成图全显）。
  - position 100%（分隔线最右）：生成图全显（当前为原图全显）。
  - 从左向右滑动：原图 → 生成图（当前为生成图 → 原图）。
  - 自动播放（autoPlay 0→100）：原图 → 生成图（当前为生成图 → 原图）。
- **不变内容**：滑块拖拽交互、键盘操作、手柄样式与图标、自动播放时长与中断逻辑、组件 Props 语义（before 仍为原图、after 仍为生成图）、对比模式导出仅下载生成图的行为。

## 3. 技术实现思路

采用"翻转裁剪方向"策略，仅修改原图层的 `clip-path`，使其由"显示在分隔线左侧"变为"显示在分隔线右侧"。生成图仍为底层铺满容器，在分隔线左侧显露。

- **当前裁剪**：`.compare-slider-before` 使用 `clip-path: inset(0 calc(100% - var(--slider-position)) 0 0)`，可见区域为左边缘到 position%，即原图显示在分隔线**左侧**。
- **变更后裁剪**：改为 `clip-path: inset(0 0 0 var(--slider-position))`，可见区域为 position% 到右边缘，即原图显示在分隔线**右侧**。
- **效果推导**：
  - position 0%：原图可见区域为 0%→100%（全显），覆盖底层生成图 → 全显原图。
  - position 100%：原图可见区域为 100%→100%（空），底层生成图完全显露 → 全显生成图。
  - 中间位置：分隔线左侧显露生成图，右侧显示原图；向右拖动使原图可见区缩小、生成图可见区扩大，呈"原图 → 生成图"过渡。
- **autoPlay 一致性**：autoPlay 从 0→100 动画，变更后即"原图 → 生成图"，恰好使组件既有注释"Start at 0 when autoPlay is on so the full original image is visible first"由原先与实际不符变为与实际一致（顺带修正潜在偏差）。
- **为何不采用"交换 beforeSrc/afterSrc 传参"**：交换传参会让 `before` 语义指向生成图、`after` 指向原图，与 Props 命名语义冲突，增加后续维护歧义；且需在桌面、移动两处调用点同步修改并调整 alt 文案。翻转裁剪方向为单点变更，保留语义清晰。
