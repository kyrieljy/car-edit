# DESIGN-20260726-005：明暗切换按钮布局统一与空状态亮色适配

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：1. 改图菜单图片预览空状态亮色下背景与周围不一致、线条文字非黑色；2. PC 端明暗切换按钮宽度与布局与中英文按钮不一致；3. 手机端顶部缺少明暗切换按钮
- **关联方案**：DESIGN-20260726-002（全站主题切换）、DESIGN-20260726-003（PC 端亮色色彩重构）、DESIGN-20260726-004（亮色主题遗漏区域补全）

---

## 1. 背景

DESIGN-20260726-002 至 004 已建立全站主题切换体系并完成 PC 端亮色色彩重构与遗漏补全。但在使用过程中发现三处遗留问题：

1. **改图菜单图片预览空状态亮色割裂**：配置模式下 `ResultPanel` 的空状态（未上传车辆图片时）在亮色主题下，预览窗口 `.result-window` 背景为 `var(--surface-3) = #f0f0f2`，与周围页面背景 `#f7f7f7` 存在色差；图标外框 `.result-empty svg` 硬编码 `rgba(0,0,0,0.5)` 黑色半透明背景，亮色下突兀；"准备生成"标题 `.result-empty p` 硬编码 `#b8bac2` 浅灰、提示文字 `.result-empty span` 使用 `var(--muted-2)` 灰色，均非黑色，与用户期望的"线条、文字均用黑色"不符。
2. **PC 端明暗切换按钮与中英文按钮视觉不统一**：`.theme-toggle` 虽注释声明"mirrors language-toggle visual style"，但实际未加入通用按钮选择器组（第 177-203 行），缺少 `display: inline-flex`、`border`、`background`、`min-height: 38px`、`padding` 等盒模型样式，也无 PC 端宽度约束（`.studio-header-actions .theme-toggle` 规则缺失），导致两个按钮宽度不一致、内部图标与文字布局不一致。
3. **手机端顶部缺少明暗切换入口**：`MobileFloatingTopBar` 顶部浮动栏当前仅有"个人中心"（`.mobile-floating-profile`）和"切换中英文"（`.mobile-floating-language`）两个按钮，无明暗切换按钮。CSS 中已预留 `.mobile-floating-theme` 类名（第 20595、20674 行），但组件未渲染对应按钮，`Moon`/`Sun` 图标未 import，`useTheme` 仅取了 `theme` 未取 `toggleTheme`。

## 2. 功能描述

### 核心用户故事

1. 作为用户，当我在亮色主题下打开配置模式且未上传车辆图片时，图片预览区域的背景应与周围环境颜色一致，中间的图标线条和文字（"准备生成"、"请先上传车辆图片，然后生成效果。"）应为黑色，视觉协调。
2. 作为 PC 端用户，顶部导航栏的明暗切换按钮应与相邻的中英文切换按钮宽度一致、内部布局一致（左边图标、右边文字），视觉对称。
3. 作为手机端用户，顶部浮动栏应在"个人中心"和"切换中英文"按钮中间增加一个明暗切换按钮，点击可在亮色/暗色间切换，交互逻辑与 PC 端完全相同。

### 功能输入输出与预期行为

**需求1 - 空状态亮色适配**：
- 入口：亮色主题 + 配置模式 + 未上传车辆图片（`!vehiclePreview && !job`）。
- 视觉生效：`.result-window` 亮色背景与周围容器背景一致（消除 `#f0f0f2` 与 `#f7f7f7` 色差）；`.result-empty svg` 图标外框背景在亮色下为透明或浅色描边（移除黑色半透明底）；`.result-empty` 的 `color`（控制图标线条 `currentColor`）、`.result-empty p`（"准备生成"）、`.result-empty span`（提示文字）在亮色下均为黑色。
- 暗色零回归：所有变更限定在 `[data-theme="light"]` 作用域，暗色表现不变。

**需求2 - PC 端明暗按钮统一**：
- 入口：PC 端（≥921px）顶部 `studio-header-actions` 区域。
- 视觉生效：`.theme-toggle` 获得与 `.language-toggle` 一致的盒模型（`display: inline-flex`、`align-items: center`、`justify-content: center`、`border: 1px solid var(--line)`、`background: var(--input-bg)`、`color: var(--text)`、`min-height: 38px`、`padding`、`border-radius: 0`）；新增 `.studio-header-actions .theme-toggle` 宽度约束（`flex: 0 0 72px`、`width: 72px`、`height: 38px`、`padding: 0`、`gap: 6px`），与 `.studio-header-actions .language-toggle` 完全对齐。内部布局保持"左图标 + 右文字"（已有 `font-size: 0` + `::after` 伪元素显示"亮/暗"，无需改动）。
- 暗色/亮色均生效：盒模型样式为通用规则，不限定主题作用域。

**需求3 - 手机端顶部明暗按钮**：
- 入口：手机端 `MobileFloatingTopBar` 顶部浮动栏。
- 视觉生效：在 `.mobile-floating-profile`（个人中心）与 `.mobile-floating-language`（中英文）按钮中间插入一个明暗切换按钮，套用已预留的 `.mobile-floating-theme` 类名，视觉风格与同组按钮一致（纯图标按钮，`Moon`/`Sun` 图标 `size={20}`，随主题切换图标）。
- 交互逻辑：复用 `useTheme()` 的 `toggleTheme`，点击切换 `data-theme`，与 PC 端逻辑完全相同。
- 补全 CSS 遗漏：`.mobile-floating-theme` 在部分规则组（transition、detached 状态、light+detached 状态）中被遗漏，需补全以保持与同组按钮的悬浮、过渡、状态切换视觉一致。

### 非功能性需求

- **零新依赖**：纯 CSS 变量与选择器覆盖 + React 组件改动，不引入新库。
- **暗色零回归**：需求1 所有变更限定在 `[data-theme="light"]` 作用域；需求2/3 的盒模型与组件改动为通用规则，对暗色无负面影响。
- **性能**：纯 CSS 切换与小型组件渲染，无性能影响。

## 3. 技术实现思路

### 整体策略

三个需求相互独立，可并行实施。需求1 采用"新增 `[data-theme="light"]` 覆盖规则"策略（与 DESIGN-004 一致）；需求2 采用"补齐盒模型 + 新增宽度约束"策略；需求3 采用"复用 PC 端交互逻辑 + 套用手机端预留类名 + 补全 CSS 遗漏规则"策略。

### 关键逻辑说明

#### 3.1 需求1：空状态亮色适配（`app/globals.css`）

当前状态与处理策略：

| 选择器 | 当前值（亮色下生效） | 处理策略 |
|--------|---------------------|----------|
| `[data-theme="light"] .result-window`（第 4989-4993 行） | `background: radial-gradient(...), var(--surface-3)`（`#f0f0f2`） | 将 `var(--surface-3)` 改为 `var(--bg)`（`#f7f7f7`），与周围页面背景一致；保留 radial-gradient 装饰（暗色下也有此装饰，亮色下已弱化为 `0.05` 透明度，可保留） |
| `.result-empty`（第 5050 行） | `color: var(--muted)`（亮色 `#5a5b62` 灰色） | 新增 `[data-theme="light"] .result-empty { color: #000; }`，使图标线条（`currentColor`）变为黑色 |
| `.result-empty svg`（第 5060 行） | `background: rgba(0,0,0,0.5)` 硬编码黑色半透明 | 新增 `[data-theme="light"] .result-empty svg { background: transparent; }`（或浅色半透明如 `rgba(0,0,0,0.04)`），移除黑色底；`border` 已使用 `var(--line)`（亮色 `#e5e5e8`），无需改动 |
| `.result-empty p`（第 5065 行） | `color: #b8bac2` 硬编码浅灰 | 新增 `[data-theme="light"] .result-empty p { color: #000; }` |
| `.result-empty span`（第 5069 行） | `color: var(--muted-2)`（亮色 `#86878d` 灰色） | 新增 `[data-theme="light"] .result-empty span { color: #000; }` |

> 说明：用户要求"线条、文字均用黑色"，故亮色下统一使用纯黑 `#000`（或 `var(--text)` 即 `#1a1a1c` 接近黑色，实施时取视觉协调者）。考虑到 `var(--text)` 为 `#1a1a1c` 接近黑色且与全局文本色一致，推荐使用 `var(--text)` 以保持与全局色彩体系一致。

#### 3.2 需求2：PC 端明暗按钮统一（`app/globals.css`）

当前 `.theme-toggle` 仅有 `font-size: 0`、`svg` 尺寸、`::after` 伪元素三组规则（第 13929-13956 行），缺少盒模型与宽度约束。处理策略：

**步骤A - 加入通用按钮选择器组**：
将 `.theme-toggle` 加入以下选择器列表，使其自动获得通用按钮样式：
- 第 177-195 行通用按钮组：获得 `border: 1px solid var(--line)`、`background: var(--input-bg)`、`color: var(--text)`、`display: inline-flex`、`align-items: center`、`justify-content: center`、`gap: 8px`
- 第 197-203 行按钮基础组：获得 `min-height: 38px`、`padding: 0 12px`、`border-radius: 0`

> 注意：`.theme-toggle` 已有 `font-size: 0 !important`（第 13930 行），会隐藏 JSX 中的文本节点，与 `::after` 伪元素配合显示"亮/暗"，加入通用组后 `gap: 8px` 会被后续 PC 端宽度约束覆盖为 `6px`，不冲突。

**步骤B - 新增 PC 端宽度约束**：
新增 `.studio-header-actions .theme-toggle` 规则，镜像第 13888-13899 行的 `.studio-header-actions .language-toggle`，锁定宽度为 72px：
- `box-sizing: border-box`
- `flex: 0 0 72px !important`、`width: 72px !important`、`min-width: 72px !important`、`max-width: 72px !important`
- `height: 38px`、`min-height: 38px`
- `padding: 0 !important`
- `gap: 6px`
- `overflow: hidden`

**步骤C - 确认现有规则无需改动**：
- `.theme-toggle` 的 `font-size: 0 !important`（第 13930 行）：保留，隐藏文本节点
- `.theme-toggle svg`（第 13934-13938 行）：`width: 15px; height: 15px; flex: 0 0 15px`：保留，与 `language-toggle svg` 一致
- `.theme-toggle::after`（第 13940-13956 行）：`content: "亮"/"暗"`、`width: 18px`、`font-size: 12px`、`font-weight: 700`：保留，与 `language-toggle::after` 一致

> 注意：`.theme-toggle` 加入第 197-203 行后会获得 `color: #d6d7dc`（硬编码浅灰），这是 `language-toggle` 的现有行为（暗色下的文字色）。但 `.theme-toggle` 已有 `font-size: 0` 隐藏文本，`::after` 伪元素的文字色会继承此 `color`。需确认亮色下 `::after` 文字是否可见——由于 `#d6d7dc` 在亮色白底上对比度不足，需新增 `[data-theme="light"] .theme-toggle { color: var(--text); }` 覆盖，确保亮色下"亮"字为深色可见。`language-toggle` 在亮色下可能也存在此问题，但本次不修复 `language-toggle` 的既有问题，仅确保 `theme-toggle` 亮色下正常。

#### 3.3 需求3：手机端顶部明暗按钮（`components/mobile/mobile-studio-app.tsx` + `app/globals.css`）

**组件改动**：
1. **import 补充**：在 `mobile-studio-app.tsx` 第 15-44 行的 `lucide-react` import 列表中加入 `Moon, Sun`。
2. **useTheme 取值**：将第 550 行 `const { theme } = useTheme()` 改为 `const { theme, toggleTheme } = useTheme()`。
3. **MobileFloatingTopBar props 扩展**：在组件 props 类型定义（第 3380-3386 行）增加 `onTheme: () => void` 与 `theme: "dark" | "light"`（或让组件内部直接调用 `useTheme`，但为保持与现有 `onLanguage`/`onProfile` 一致的 prop 传递模式，推荐通过 props 传入）。
4. **调用处传参**：在第 668-680 行 `<MobileFloatingTopBar ... />` 调用处增加 `onTheme={toggleTheme}` 与 `theme={theme}`。
5. **插入按钮**：在第 3398 行（`mobile-floating-profile` 按钮 `</button>` 之后）与第 3399 行（`mobile-floating-language` 按钮）之间，插入明暗切换按钮：
   - `className="mobile-floating-theme"`
   - `data-theme={theme}`
   - `onClick={onTheme}`
   - `aria-label` 根据 theme 显示"Switch to light theme"/"切换到深色主题"
   - 图标：`theme === "dark" ? <Moon size={20} /> : <Sun size={20} />`（size 与同组 `Languages size={20}`、`UserRound size={19}` 协调，取 20）

**CSS 补全**：
`.mobile-floating-theme` 类名已在以下规则组中出现，但部分规则组遗漏，需补全：

| 规则组（行号） | 当前是否含 `.mobile-floating-theme` | 处理 |
|----------------|-------------------------------------|------|
| 第 20595 行（基础定义组） | 已含 | 无需改动 |
| 第 20673-20676 行（light 组） | 已含 | 无需改动 |
| 第 20647-20652 行（transition 过渡组） | 缺失（仅 menu/profile/language/title） | 补充 `.mobile-floating-theme`，获得过渡动画 |
| 第 20660-20663 行（detached 状态组） | 缺失（仅 menu/profile/language/title） | 补充 `.mobile-floating-theme`，获得 detached 浮起状态的样式 |
| 第 20684-20687 行（light+detached 组） | 缺失（仅 menu/profile/language/title） | 补充 `.mobile-floating-theme`，获得亮色下 detached 状态的样式 |

> 说明：`detached` 状态是 `MobileFloatingTopBar` 的滚动浮起状态（滚动时顶部栏脱离顶部形成悬浮卡片效果），同组按钮需同步样式以保持视觉一致。
