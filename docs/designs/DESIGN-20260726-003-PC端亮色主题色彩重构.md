# DESIGN-20260726-003：PC端亮色主题色彩重构

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：当前明亮主题下 PC 端色彩不美观，需将主色/辅助色调整为 #F7F7F7/#FFFFFF、文字近黑、组件避免黑色背景，并修复 PC 端最底层背景未随主题切换的问题
- **关联方案**：DESIGN-20260726-002（全站主题切换功能，已实施）

---

## 1. 背景

DESIGN-20260726-002 已落地全站主题切换功能，建立了 `[data-theme="light"]` CSS 变量覆盖集与 `theme-context.tsx` 全局 Context。但实际使用中，PC 端亮色主题存在三类视觉问题：

1. **色彩取值不够美观**：当前亮色变量 `--bg: #f5f5f7`、`--surface: rgba(245,245,247,0.92)` 偏灰且半透明，层次感不足，与用户期望的纯净白系（`#F7F7F7` 底 + `#FFFFFF` 卡面）存在差距。
2. **PC 端最底层背景未切换**：`.app-shell`（第 76-87 行）硬编码 `#000` + 金色径向渐变 + `::before`/`::after` 侧边金色纹理装饰，完全不走 CSS 变量，亮色模式下仍是纯黑底，是用户最直观感知到的"背景没换"问题。
3. **PC 端 58 处硬编码深色背景零响应**：经全量排查，`globals.css` 中 PC 端有 58 处 `background: #0xxxxx` 或 `background: rgba(0,0,0,…)` 直接写死的深色背景，分布在管理后台、工作室控件、图片容器、弹窗遮罩、认证按钮、Chat 容器、工作流设计器等 7 个区域，全部不响应亮色主题。现有 38 处 `[data-theme="light"]` 覆盖中 37 处限定在 `.mobile-studio-app` 移动端作用域，PC 端几乎零亮色覆盖。

此外，`components/car-mod-studio.tsx` 第 3752 行存在一处内联硬编码 `#050506`（结果窗口 `--paint` 回退值）。

本次需求在 DESIGN-20260726-002 架构基础上，重构 PC 端亮色色彩体系，使亮色主题达到美观、纯净、一致的视觉效果。

## 2. 功能描述

### 核心用户故事

作为用户，当我切换到明亮主题时，PC 端全站（工作室主界面、管理后台、认证弹窗、订阅弹窗、工作流设计器等所有页面）应呈现纯净的白系视觉：底层背景为 `#F7F7F7`，卡片/面板浮层为 `#FFFFFF`，文字为近黑 `#1a1a1c`，所有组件不再出现黑色背景，最底层的 `.app-shell` 背景也随主题切换为浅色。

### 功能输入输出与预期行为

- **入口**：无需新增入口，复用 DESIGN-20260726-002 已建立的主题切换按钮（`theme-toggle`），用户切换至 `light` 即生效。
- **视觉生效范围**：PC 端全站所有页面立即响应，无需刷新。
- **色彩规范**：
  - 主色（底层背景 `--bg`）：`#F7F7F7`
  - 辅助色（卡片/面板表面 `--surface` / `--panel` / `--surface-2` / `--surface-3`）：`#FFFFFF` 及其衍生浅灰
  - 文字色（`--text`）：`#1a1a1c`（近黑，保持当前值）
  - 品牌金色（`--yellow` / `--yellow-2`）：保留不变
  - `.app-shell` 装饰（径向金色光晕 + 侧边金色纹理）：亮色下大幅弱化或移除
- **持久化**：复用现有 `THEME_STORAGE_KEY` localStorage 机制，无需改动。

### 非功能性需求

- **零新依赖**：纯 CSS 变量调整 + 选择器覆盖，不引入任何新库。
- **不影响暗色主题**：所有变更仅作用于 `[data-theme="light"]` 作用域或新增亮色覆盖规则，暗色 `:root` 变量与现有暗色样式不动。
- **不影响移动端**：移动端已有完善的 `.mobile-studio-app[data-theme="light"]` 覆盖体系，本次不改动移动端样式。
- **性能**：纯 CSS 变量与选择器切换，无重渲染、无网络请求。

## 3. 技术实现思路

### 整体策略

采用"变量更新 + 底层覆盖 + 逐项替换"三层处理，所有改动限定在 `[data-theme="light"]` 作用域内，确保暗色主题零影响：

1. **变量层**：更新 `[data-theme="light"]` 块中的核心变量取值，使其符合 `#F7F7F7`/`#FFFFFF` 色彩规范。
2. **底层覆盖层**：为 `.app-shell` 及其装饰元素（`::before`/`::after`）新增 `[data-theme="light"]` 亮色覆盖规则，替换硬编码的黑色底与金色装饰。
3. **逐项替换层**：对 58 处 PC 端硬编码深色背景，按区域分类处理——能直接替换为 CSS 变量引用的替换之，不能直接替换的（如特定装饰、渐变内嵌色）新增 `[data-theme="light"]` 选择器覆盖。

### 关键逻辑说明

#### 3.1 亮色变量取值更新（globals.css 第 26-40 行）

更新 `[data-theme="light"]` 块的变量取值，对齐用户指定的色彩规范：

| 变量 | 当前值 | 调整后 | 说明 |
|------|--------|--------|------|
| `--bg` | `#f5f5f7` | `#F7F7F7` | 主色，底层背景 |
| `--panel` | `rgba(255,255,255,0.85)` | `rgba(255,255,255,0.92)` | 卡片面板，提高不透明度增强白感 |
| `--surface` | `rgba(245,245,247,0.92)` | `rgba(255,255,255,0.92)` | 辅助色，纯白基底 |
| `--surface-2` | `rgba(238,238,240,0.85)` | `rgba(247,247,247,0.85)` | 次级表面，极浅灰 |
| `--surface-3` | `#ececef` | `#F0F0F2` | 三级表面 |
| `--line` | `#d1d1d6` | `#E5E5E8` | 边框线，略柔化 |
| `--line-soft` | `rgba(0,0,0,0.1)` | 保持 | 软边框 |
| `--text` | `#1a1a1c` | 保持 `#1a1a1c` | 近黑文字 |
| `--muted` | `#5a5b62` | 保持 | 辅助文字 |
| `--muted-2` | `#86878d` | 保持 | 次级辅助文字 |
| `--accent` | `#1a1a1c` | 保持 | 强调色 |
| `--shadow` | `rgba(0,0,0,0.12)` | 保持 | 阴影 |
| `--yellow` / `--yellow-2` | 不变 | 不变 | 品牌金色保留 |
| `color-scheme` | `light` | 保持 | — |

#### 3.2 .app-shell 底层背景修复（globals.css 第 76-111 行）

`.app-shell` 是 PC 端最外层容器，当前硬编码 `#000` 底 + 金色径向渐变。这是用户指出的核心问题。

**暗色现状（不动）**：
- `.app-shell` background：`radial-gradient(金色光晕) , #000`
- `.app-shell::before` / `::after`：侧边金色纹理装饰（线性渐变 + 径向点阵）

**亮色覆盖策略**：
- 新增 `[data-theme="light"] .app-shell` 规则，将 background 覆盖为 `#F7F7F7` 纯底，或叠加一层极淡的金色径向渐变（透明度降至 0.04-0.06）以保留品牌暗示但不显突兀。
- 新增 `[data-theme="light"] .app-shell::before` / `[data-theme="light"] .app-shell::after` 规则，将侧边金色纹理的透明度大幅降低（mask-image 调整或 background 透明度降至 0.08-0.12），或直接 `display: none` 移除。推荐"弱化保留"方案，使亮色下仍有微妙的品牌纹理暗示，与暗色形成呼应。

#### 3.3 PC 端 58 处硬编码深色背景分类处理

按区域与性质分四类处理策略：

**第一类：大面积底色 → 直接替换为 CSS 变量**

这类硬编码是组件的主背景色，应替换为 `var(--bg)` / `var(--surface)` / `var(--surface-2)` / `var(--surface-3)` 引用，使其自动响应明暗主题。涉及：

| 区域 | 选择器 | 当前值 | 替换为 |
|------|--------|--------|--------|
| Chat 容器 | `.chat-mode-shell` / `.chat-search` / `.chat-workspace` | `#09090b` / `#030307` | `var(--bg)` 或 `var(--surface)` |
| 管理后台底色 | `.admin-shell` | `#080808` | `var(--bg)` |
| 管理后台侧栏 | `.admin-sidebar` | `#0c0c0d` | `var(--surface-2)` |
| 工作流设计器 | `.workflow-designer` / `.workflow-template-sidebar` / `.workflow-properties` | `#0b1020` / `#0d1322` | `var(--bg)` / `var(--surface-2)` |
| 工作流搜索/输入 | `.workflow-search` / `.workflow-prop-body input` | `#080d18` | `var(--surface-3)` |
| 图片容器 | `.upload-tile img` 及其变体 | `#050505` | `var(--surface-3)` |
| 历史缩略图 | `.history-list button` | `#0c0e12` | `var(--surface-3)` |
| 管理后台灯箱面板 | `.admin-image-lightbox-panel` | `#050607` | `var(--surface)` |

**第二类：输入框/控件半透明深色底 → 替换为浅色半透明变量**

这类是 `rgba(0,0,0,0.3~0.5)` 的半透明黑底输入框/控件，亮色下应为浅色半透明。涉及工作室控件（D区12处）、管理后台表单输入等。策略：将这些 `rgba(0,0,0,X)` 替换为 `var(--surface-2)` 或新增浅色半透明变量（如 `--input-bg`），在 `[data-theme="light"]` 中定义为 `rgba(0,0,0,0.04)` 等浅色值。

为避免改动暗色现有表现，推荐方式：引入新语义变量 `--input-bg`（暗色 = `rgba(0,0,0,0.4X)`，亮色 = `rgba(0,0,0,0.04)`），将硬编码替换为 `var(--input-bg)`。

**第三类：弹窗遮罩 → 保留或微调**

弹窗/灯箱遮罩（`.modal-backdrop`、`.preview-lightbox`、`.admin-image-lightbox` 等，`rgba(0,0,0,0.6~0.82)`）在亮色模式下**仍应保持暗遮罩**以突出弹窗内容，这是合理的 UI 模式。这类**不改动**或仅微降透明度。但 `.pricing-backdrop` / `.subscribe-modal.pricing-template` 的纯 `#000` 底应替换为 `rgba(0,0,0,0.82)` 统一为半透明遮罩。

**第四类：深色强调按钮 → 保留或新增亮色覆盖**

认证模板按钮（`.auth-template-code button`、`.auth-template-submit` 等 `#050505`）是深色强调按钮，暗色下作为主操作按钮。亮色下这类按钮可保留深色（深色按钮在白底上作为 CTA 是合理设计），或新增 `[data-theme="light"]` 覆盖为浅色描边按钮。推荐**保留深色**——白底上的深色 CTA 按钮对比度高，符合设计直觉，且减少改动量。`.admin-optimus` 选中态的 `#080706` 同理保留。

#### 3.4 car-mod-studio.tsx 内联硬编码修复

第 3752 行 `style={{ "--paint": selectedPaint?.hex ?? "#050506" }}` 中的 `#050506` 是车漆色回退值。该值是业务数据回退（无选中车漆时的默认色），非 UI 主题色。但为避免亮色下结果窗口出现近黑底，将回退值改为中性灰（如 `#1a1a1c`，与 `--text` 一致）或移除回退交由 CSS 控制。由于这是业务数据回退而非主题色，优先级较低，可作为附带修复项。

#### 3.5 渐变内嵌深色处理

部分深色值嵌在 `linear-gradient` / `radial-gradient` 内（如 `.result-window`、`.chat-bg`），无法直接替换单个变量。策略：为这些选择器新增 `[data-theme="light"]` 覆盖规则，整体替换渐变为浅色版本。涉及选择器需在实施时定向扫描 `gradient` 行确认完整清单。

## 7. 实施步骤

1. **更新亮色变量取值**：修改 `app/globals.css` 第 26-40 行 `[data-theme="light"]` 块，按 3.1 节表格更新 `--bg`、`--panel`、`--surface`、`--surface-2`、`--surface-3`、`--line` 等变量取值；新增 `--input-bg` 语义变量（暗色 `:root` 中定义为 `rgba(0,0,0,0.4)`，亮色 `[data-theme="light"]` 中定义为 `rgba(0,0,0,0.04)`）。
2. **修复 .app-shell 底层背景**：在 `app/globals.css` 中新增 `[data-theme="light"] .app-shell` 规则覆盖 background 为 `#F7F7F7` 底（可叠加极淡金色径向渐变，透明度 0.04-0.06）；新增 `[data-theme="light"] .app-shell::before` / `::after` 规则弱化侧边金色纹理（透明度降至 0.08-0.12 或调整 mask-image）。
3. **替换第一类大面积底色**：按 3.3 节第一类表格，将 `.chat-mode-shell`、`.chat-search`、`.chat-workspace`、`.admin-shell`、`.admin-sidebar`、`.workflow-designer`、`.workflow-template-sidebar`、`.workflow-properties`、`.workflow-search`、`.workflow-prop-body input`、`.upload-tile img` 及变体、`.history-list button`、`.admin-image-lightbox-panel` 等选择器的硬编码深色替换为对应 CSS 变量引用。
4. **替换第二类控件半透明深色底**：将工作室控件与管理后台表单输入的 `rgba(0,0,0,0.3~0.5)` 背景替换为 `var(--input-bg)` 或 `var(--surface-2)`；涉及第 174、284、334、508、1501、3291、3533、8589、8616、11727、11839 行等选择器。
5. **处理第三类弹窗遮罩**：将 `.pricing-backdrop`、`.subscribe-modal.pricing-template` 的纯 `#000` 底替换为 `rgba(0,0,0,0.82)` 半透明遮罩；其余 `.modal-backdrop`、`.preview-lightbox`、`.admin-image-lightbox` 等半透明遮罩保留不动。
6. **确认第四类深色按钮策略**：`.auth-template-code button`、`.auth-template-submit`、`.admin-optimus` 选中态等深色强调按钮保留深色（白底 CTA 对比合理），不改动；实施时目测确认协调性。
7. **处理渐变内嵌深色**：定向扫描 `globals.css` 中含 `gradient` 且嵌有深色值的选择器（`.result-window`、`.chat-bg` 等），为每处新增 `[data-theme="light"]` 覆盖规则替换为浅色渐变版本。
