# DESIGN-20260729-001：订单与支付模块接入

## 元信息
- **创建日期**：2026-07-29
- **状态**：草稿
- **关联需求**：接入订单和支付两个模块，当前版本不接入实际支付接口（未来接入）。用户界面订阅添加支付按钮（免费版不可用），点击直接完成订阅；管理后台添加订单界面，支持多维度筛选；用户个人中心添加订单入口。

---

## 1. 背景

当前系统的计费模块已具备基础数据层（`payment_orders` 表、`subscriptions` 表、`membership_plans` 表等），但自助支付流程被禁用（`checkout` 和 `mock-paid` 接口返回 403 `SUBSCRIPTION_MANAGED_BY_ADMIN`）。管理后台没有订单管理视图，用户个人中心也没有订单查看入口。

本次需求旨在：
1. 在当前版本中启用模拟支付流程，使用户可以通过界面自助完成套餐订阅（不接入真实支付网关）。
2. 为管理员提供订单管理能力（查看、筛选所有用户订单）。
3. 为用户提供订单查看能力（在个人中心查看自己的购买记录）。

为未来接入真实支付接口（微信支付、支付宝）预留扩展空间。

---

## 2. 功能描述

### 2.1 用户界面 — 订阅弹窗支付按钮

**用户故事**：作为用户，我在订阅弹窗中看到各套餐的支付按钮，点击后可直接完成订阅。

**预期行为**：
- 订阅弹窗（`SubscribeModal`）中每个付费套餐（pro / max）卡片添加"支付"按钮。
- 免费版（free）按钮置为 `disabled` 状态，显示为不可用。
- 点击付费套餐的支付按钮后，前端串行调用：
  1. `POST /api/billing/checkout` — 创建支付订单
  2. `POST /api/billing/mock-paid` — 模拟支付完成
- 支付成功后，刷新用户计费状态（`billing`），关闭弹窗，并显示成功提示。
- 整个流程无真实支付 UI（无二维码、无支付网关跳转），点击即完成。

**非功能性需求**：
- 支付过程中按钮显示 loading 状态，防止重复点击。
- 错误时展示中文/英文错误提示（按当前语言）。

### 2.2 管理后台 — 订单管理页面

**用户故事**：作为管理员，我可以在管理后台查看所有用户的订单记录，并按时间范围、用户、订阅套餐进行筛选。

**预期行为**：
- 管理后台左侧导航栏新增"订单"标签（`orders`）。
- 点击后右侧展示订单表格页面。
- 表格字段：订单号、用户（用户名 + 手机号）、订阅套餐、金额、支付方式、状态、创建时间。
- 筛选栏支持：
  - **时间范围**：起始日期 ~ 截止日期（日期选择器）
  - **用户**：文本输入框，模糊匹配用户名或手机号
  - **订阅套餐**：下拉选择（free / pro / max）
- 表格按创建时间倒序排列。

### 2.3 用户个人中心 — 我的订单

**用户故事**：作为用户，我可以在个人中心查看自己的支付购买记录。

**预期行为**：
- **PC 端**（`DesktopAccountPanel`）：在"概览"页面添加"我的订单"入口按钮，点击后切换至订单列表视图（新增 `orders` 模式）。列表展示：订单号、套餐、金额、支付方式、状态、时间。
- **移动端**（`MobileProfilePage`）：在个人中心概览页面添加"我的订单"入口，点击进入订单列表子页面（新增 `orders` section）。列表字段与 PC 端一致。
- 仅展示当前登录用户的订单，按创建时间倒序排列。

### 2.4 额外补充内容

经分析，支付和订单模块还有以下内容需要同步开发或调整：

1. **数据库字段同步**：`docs/DB_SCHEMA.md` 中 `payment_orders` 表的字段描述与实际代码不一致（文档写 `amount` 和 `paid_at`，实际代码为 `amount_cents` 且无 `paid_at` 字段；实际表中有 `method` 字段但文档未提及）。需要同步文档。
2. **支付方式展示**：当前 `payment_orders` 表已存储 `method` 字段（`wechat` / `alipay`），但类型定义中 `PaymentOrder` 未在 DB 文档中体现，需在订单列表中展示。
3. **订单状态扩展**：当前状态为 `pending` / `paid` / `failed`。未来接入真实支付时可能需要 `refunded` 等状态，本次在类型层面预留。
4. **订阅有效期**：当前 `completeMockPayment` 中订阅有效期固定为 30 天（`now + 1000 * 60 * 60 * 24 * 30`），未来接入真实支付后需要根据支付周期（月付/年付）计算，本次保持现有逻辑但需在代码中预留注释。
5. **用户套餐降级限制**：当前代码允许用户从付费套餐切换回免费套餐（`selectedIsPaidToFree` 逻辑），本次启用支付后需要确认是否允许降级。基于现有需求，保留降级能力（通过选择 free 套餐触发）。
6. **订单数据关联展示**：管理员订单表格需要展示用户信息（用户名、手机号），因此订单查询需要 JOIN `users` 表。
7. **支付成功后额度刷新**：当前 `completeMockPayment` 返回 `getBillingStatus(input.userId)`，前端需要正确消费此响应更新 `billing` 状态。

## 3. 技术实现思路

### 3.1 整体策略

采用"最小改动 + 预留扩展"的策略：
- 后端：复用现有的 `createPaymentOrder` 和 `completeMockPayment` 函数，移除 checkout/mock-paid 接口的禁用逻辑；新增订单查询 API。
- 前端：改造现有组件，新增订单展示视图，保持与现有 UI 风格（暗黑奢华 / 纯白亮色双主题）一致。

### 3.2 后端实现

#### 启用模拟支付流程
- `app/api/billing/checkout/route.ts`：移除返回 403 的禁用逻辑，恢复为正常创建订单流程。请求体接收 `{ planId, method, cycle }`（`cycle` 保留字段，当前版本固定处理为 monthly）。调用 `createPaymentOrder` 创建订单后返回订单对象。
- `app/api/billing/mock-paid/route.ts`：移除返回 403 的禁用逻辑，恢复为正常完成支付流程。请求体接收 `{ orderId }`，调用 `completeMockPayment` 完成支付，返回更新后的 `EntitlementStatus`（即 `billing` 对象）。

#### 新增订单查询 API
- `app/api/billing/orders/route.ts`（需认证）：
  - `GET` 方法，调用 `getPaymentOrders(userId)` 查询当前用户的所有订单。
  - 返回 `{ orders: PaymentOrder[] }`。
- `app/api/admin/orders/route.ts`（需管理员权限）：
  - `GET` 方法，支持 Query 参数筛选：`startDate`, `endDate`, `userQuery`（用户名/手机号模糊匹配）, `planId`。
  - 调用 `getAllPaymentOrders(filters)` 查询所有订单（JOIN `users` 表获取用户信息）。
  - 返回 `{ orders: AdminPaymentOrder[] }`，其中 `AdminPaymentOrder` 包含用户基本信息（`userName`, `userPhone`）。

#### 数据库层扩展
- `lib/server/db.ts`：
  - 新增 `getPaymentOrders(userId: string): PaymentOrder[]` — 查询指定用户的订单（已存在 `paymentOrders` 私有函数，需包装为导出函数）。
  - 新增 `getAllPaymentOrders(filters): AdminPaymentOrder[]` — 管理员查询所有订单，支持多维度筛选。
  - 确认 `payment_orders` 表字段与类型定义一致。

### 3.3 前端实现

#### 订阅弹窗改造（`SubscribeModal`）
- 将 `USER_SUBSCRIPTION_CHECKOUT_ENABLED` 改为 `true`，或移除该开关。
- 保留支付方式选择（微信/支付宝），但简化交互：点击套餐卡片的"支付"按钮后直接触发完整支付流程（checkout → mock-paid），无需二次确认弹窗。
- 免费版（free）卡片按钮置为 `disabled`，文案为"免费版不可用"或保持现有"保留免费版"但禁用。
- 在 `completeCheckout` 函数中，付费套餐直接串行调用 checkout 和 mock-paid，不再弹出支付方式选择弹窗。

#### 管理后台订单页面（`AdminConsole`）
- `AdminTab` 类型新增 `"orders"`。
- `generationNavItems` 数组中添加 `{ id: "orders", label: "订单", sub: "支付与订阅", icon: <CreditCard /> }`（需从 lucide-react 导入 `CreditCard` 或 `Receipt`）。
- `adminTabTitle` 函数添加 `orders` 映射。
- 新增订单表格渲染逻辑：
  - 从 `/api/admin/orders` 获取数据。
  - 筛选栏：日期选择器（起止）、文本输入（用户查询）、下拉选择（套餐）。
  - 表格使用现有表格样式（参考 `usage` 或 `users` tab 的实现风格）。

#### PC 端个人中心订单（`DesktopAccountPanel`）
- `AccountPanelMode` 类型新增 `"orders"`。
- 概览页面添加"我的订单"按钮（使用 `Receipt` 或 `CreditCard` 图标）。
- 新增 `orders` 模式渲染：从 `/api/billing/orders` 获取数据，展示订单列表。
- 列表字段：订单号、套餐名称、金额（元）、支付方式（微信/支付宝）、状态、创建时间。

#### 移动端个人中心订单（`MobileProfilePage`）
- `MobileProfileSection` 类型新增 `"orders"`。
- 概览页面添加"我的订单"入口行（与"消息通知"等同级）。
- 新增 `orders` section 渲染：订单列表，样式与移动端其他子页面保持一致（白色卡片、列表项带分隔线）。

### 3.4 与现有模块的交互

- **认证模块**：新增 API 复用现有的 `requireUser` 和 `requireAdminUser` 认证守卫。
- **计费模块**：复用现有的 `createPaymentOrder`、`completeMockPayment`、`getBillingStatus` 函数。
- **账户消息模块**：支付流程自动创建账户消息（已有逻辑），无需额外改动。
- **审计日志模块**：支付流程自动写入审计日志（已有逻辑），无需额外改动。
