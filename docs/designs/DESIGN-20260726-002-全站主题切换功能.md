# DESIGN-20260726-002：全站主题切换功能

## 元信息
- **创建日期**：2026-07-26
- **状态**：草稿
- **关联需求**：在中英文切换按钮旁边添加主题切换按钮，点击后整个页面在暗色调（当前效果）和明亮色调（偏白色）之间切换

---

## 1. 背景

当前项目采用纯黑底色 + 金黄色品牌色的暗黑奢华 UI 风格（ADR-0004），全局 `app/globals.css` 仅定义了 `:root` 暗色 CSS 变量集，`color-scheme: dark` 写死，桌面端无任何主题切换入口。

现有主题相关代码存在以下问题：
- `components/car-mod-studio.tsx` 第 730 行有一个 `mobileTheme` 状态（`"dark"|"light"`），但第 826-830 行被**强制写死为 dark**，且仅作用于移动端。
- 第 1671-1674 行已存在 `mobile-theme-toggle` 按钮，但 CSS 第 16520 行 `display: none`，**桌面端不可见**。
- `components/theme-provider.tsx` 引用了 `next-themes`，但该依赖**未安装**且 `app/layout.tsx` 未使用，属于未落地的残留文件。
- 移动端 `globals.css` 中已有大量 `[data-theme="light"]` 样式覆盖（第 1801、17421、17458、17717 等行），但桌面端无对应亮色变量集。

用户希望在中英文切换按钮（第 1667 行）旁添加主题切换按钮，实现全站暗/亮色调切换，覆盖桌面端、移动端及所有子页面（管理后台、认证弹窗等）。

## 2. 功能描述

### 核心用户故事
作为用户，我希望在页面头部中英文切换按钮旁看到一个主题切换按钮，点击后整个站点（含工作室主界面、移动端、管理后台、认证弹窗、订阅弹窗等所有页面）在暗色调与明亮色调之间切换，并能记住我的偏好。

### 功能输入输出与预期行为
- **入口**：桌面端 `components/car-mod-studio.tsx` 头部 `.studio-header-actions` 容器内，紧邻语言切换按钮（第 1667 行）添加主题切换按钮。
- **按钮交互**：点击在 `dark` ↔ `light` 之间切换；按钮图标与文案随状态变化（暗色显示月亮图标+"暗"，亮色显示太阳图标+"亮"，与现有移动端 `mobile-theme-toggle` 第 1671-1674 行的交互模式保持一致）。
- **视觉生效范围**：全站所有页面立即响应主题切换，无需刷新。
- **状态初始化策略**：
  1. 首次访问（localStorage 无记录）：读取 `window.matchMedia('(prefers-color-scheme: light)')` 系统偏好作为初始值；
  2. 已有记录：读取 localStorage 中持久化的主题值；
  3. 默认回退：若系统偏好不可用或为暗色，默认 `dark`。
- **持久化**：用户每次切换后写入 localStorage，刷新页面后保持上次选择。
- **DOM 表达**：在 `<html>` 元素上设置 `data-theme="dark"` 或 `data-theme="light"` 属性，所有 CSS 变量通过该属性选择器覆盖。

### 非功能性需求
- **零新依赖**：不引入 `next-themes`，使用原生 React Context + CSS 变量实现，与项目纯 CSS 技术栈一致。
- **无闪烁**：首次加载时需在客户端 hydration 前通过内联脚本设置 `data-theme`，避免亮色变量集加载前的暗色闪烁（FOUC）。
- **性能**：主题切换为纯 CSS 变量切换，不触发重渲染，无网络请求。

## 3. 技术实现思路

### 整体策略
采用"全局 Context + data-theme 属性 + CSS 变量覆盖集"的三层架构：

1. **状态层**：新建 `components/theme-context.tsx`，导出 `ThemeProvider` 与 `useTheme` hook。`ThemeProvider` 为客户端组件，管理 `theme` 状态，负责读写 localStorage、监听系统偏好变化、同步 `<html>` 元素的 `data-theme` 属性。
2. **注入层**：在 `app/layout.tsx` 用 `ThemeProvider` 包裹 `children`，使全站所有客户端组件均可通过 `useTheme` 读取或切换主题。
3. **样式层**：在 `app/globals.css` 的 `:root` 之后新增 `[data-theme="light"]` 变量覆盖集，覆盖桌面端所有核心变量（`--bg`、`--panel`、`--surface`、`--surface-2`、`--surface-3`、`--line`、`--line-soft`、`--text`、`--muted`、`--muted-2`、`--accent`、`--shadow`、`color-scheme` 等），形成偏白色的明亮色调。移动端已有的 `[data-theme="light"]` 样式保留并复用。

### 关键逻辑说明

#### 3.1 主题状态管理（theme-context.tsx）
- **Context 值结构**：`{ theme: Theme; toggleTheme: () => void; setTheme: (t: Theme) => void }`，其中 `type Theme = "dark" | "light"`。
- **存储键**：复用现有 `MOBILE_THEME_STORAGE_KEY`（值为 `"car-mod-studio-mobile-theme"`），避免迁移历史用户偏好；或新增 `THEME_STORAGE_KEY = "car-mod-studio-theme"`（推荐新增，语义更清晰，与"全站主题"概念对齐）。本方案采用**新增独立键**，旧 `mobileTheme` 的 localStorage 记录可忽略（因其曾被强制写死为 dark）。
- **初始化流程**（在 `useEffect` 中执行，避免 SSR 不一致）：
  1. 读取 `localStorage.getItem(THEME_STORAGE_KEY)`；
  2. 若有有效值（`"dark"` 或 `"light"`），直接使用；
  3. 若无，调用 `window.matchMedia('(prefers-color-scheme: light)').matches` 判断系统偏好，匹配则初始化为 `light`，否则 `dark`；
  4. 同步设置 `document.documentElement.setAttribute('data-theme', theme)`。
- **切换逻辑**：`toggleTheme` 切换 `theme` 状态，同步写入 localStorage 并更新 `<html>` 的 `data-theme` 属性。
- **系统偏好监听**（可选增强）：通过 `matchMedia.addEventListener('change', ...)` 监听系统主题变化，但**仅当 localStorage 无用户记录时**跟随系统。本方案默认实现此监听以符合"跟随系统偏好"需求。
- **防闪烁内联脚本**：在 `app/layout.tsx` 的 `<head>` 内插入一段阻塞式 `<script>`，在 React hydration 前读取 localStorage 并设置 `<html data-theme>`，避免首屏闪烁。脚本逻辑与 `theme-context.tsx` 初始化逻辑保持一致。

#### 3.2 现有 mobileTheme 状态的统一
- **car-mod-studio.tsx 改造**：
  - 移除第 730 行 `mobileTheme` state 定义、第 826-830 行强制写死 dark 的 useEffect、第 844-850 行 `toggleMobileTheme` 函数；
  - 改为 `const { theme, toggleTheme } = useTheme()`；
  - 第 1671-1674 行 `mobile-theme-toggle` 按钮的 `data-theme={mobileTheme}` 与 `onClick={toggleMobileTheme}` 改为绑定 `theme` 与 `toggleTheme`；
  - 移除该按钮的 `mobile-theme-toggle` 类名（该类名 CSS 中 `display: none` 导致桌面端不可见），改用与语言切换按钮一致的样式类（如复用 `language-toggle` 样式或新增 `theme-toggle` 类），使其在桌面端可见。
- **mobile-studio-app.tsx 改造**：
  - 移除第 139-145 行 Props 中的 `mobileTheme`、`toggleMobileTheme`；
  - 内部改用 `useTheme()` 获取主题状态；
  - 第 771 行语言切换按钮旁的主题切换按钮（若有）同样改用 `useTheme`；
  - 调用方（`car-mod-studio.tsx` 中渲染移动端组件处）移除 `mobileTheme`/`toggleMobileTheme` 的 props 传递。
- **状态提升结果**：主题状态从 `car-mod-studio.tsx` 局部 state 提升为全局 Context，桌面端与移动端共享同一份主题状态，切换任一端另一端同步生效。

#### 3.3 CSS 变量覆盖集（globals.css）
- 在 `:root` 块之后新增 `[data-theme="light"]` 块，覆盖以下变量为偏白色调：
  - `color-scheme: light`
  - `--bg: #f5f5f7`（偏白浅灰底）
  - `--panel: rgba(255, 255, 255, 0.85)`
  - `--surface: rgba(245, 245, 247, 0.92)`
  - `--surface-2: rgba(238, 238, 240, 0.85)`
  - `--surface-3: #ececef`
  - `--line: #d1d1d6`
  - `--line-soft: rgba(0, 0, 0, 0.1)`
  - `--text: #1a1a1c`
  - `--muted: #5a5b62`
  - `--muted-2: #86878d`
  - `--accent: #1a1a1c`
  - `--shadow: 0 28px 90px rgba(0, 0, 0, 0.12)`
  - 品牌色 `--yellow` / `--yellow-2` 保持不变（金色在亮色背景下仍可识别，维持品牌一致性）
- **移动端变量**：现有 `[data-theme="light"]` 下移动端 `--mobile-bg` 等覆盖（第 1801、17421 等行）保留，与桌面端变量集合并存在同一 `[data-theme="light"]` 选择器下。
- **硬编码颜色排查**：需排查 `globals.css` 及组件内联样式中是否存在未使用 CSS 变量的硬编码颜色（如 `#000`、`#fff`、`rgba(0,0,0,...)`），此类颜色在亮色模式下不会自动切换，需逐一替换为变量引用或补充到 `[data-theme="light"]` 覆盖中。这是本方案的主要工作量与风险点。

#### 3.4 与现有 theme-provider.tsx 的关系
- 现有 `components/theme-provider.tsx` 引用未安装的 `next-themes`，本方案**不启用**该文件。
- 方案实施时保留该文件不动（避免误删影响其他潜在引用），新增独立的 `components/theme-context.tsx` 承载主题逻辑。若后续确认无其他引用，可在 `free-task` 中清理该残留文件。

## 7. 实施步骤

1. **新增主题 Context**：创建 `components/theme-context.tsx`，实现 `ThemeProvider`（含初始化、localStorage 读写、系统偏好监听、`<html data-theme>` 同步）与 `useTheme` hook，`type Theme = "dark" | "light"`，存储键 `THEME_STORAGE_KEY = "car-mod-studio-theme"`。
2. **改造根布局**：修改 `app/layout.tsx`，用 `ThemeProvider` 包裹 `children`；在 `<head>` 插入防闪烁内联脚本（逻辑：读 localStorage → 无则读 `prefers-color-scheme` → 设置 `document.documentElement.dataset.theme`）。
3. **新增亮色变量集**：在 `app/globals.css` 的 `:root` 块之后新增 `[data-theme="light"]` 块，覆盖核心 CSS 变量为偏白色调（具体取值见 3.3 节）。
4. **改造桌面端主组件**：修改 `components/car-mod-studio.tsx`，移除 `mobileTheme` state（第 730 行）、强制 dark 的 useEffect（第 826-830 行）、`toggleMobileTheme` 函数（第 844-850 行）；引入 `useTheme()`；将第 1671-1674 行按钮改为绑定全局 `theme`/`toggleTheme`，移除 `mobile-theme-toggle` 类名（解除 `display:none`），改用桌面端可见的样式类（如复用 `language-toggle` 样式）。
5. **改造移动端组件**：修改 `components/mobile/mobile-studio-app.tsx`，移除 `mobileTheme`/`toggleMobileTheme` Props（第 139-145 行）；内部改用 `useTheme()`；更新第 771 行附近主题切换按钮绑定；在 `car-mod-studio.tsx` 中移除向该组件传递的对应 props。
6. **排查并替换硬编码颜色**：全局搜索 `globals.css` 及组件文件中的硬编码颜色（`#000`、`#fff`、`#000000`、`#ffffff`、`rgba(0,0,0`、`rgba(255,255,255` 等），替换为 CSS 变量引用或补充到 `[data-theme="light"]` 覆盖集。重点排查 `admin-console.tsx`、`auth-modal.tsx`、`subscribe-modal.tsx`。
7. **验证编译**：运行 `npm run lint` 与 `npm run dev`，确认无 TypeScript 错误与 ESLint 警告。
8. **更新文档**：更新 `docs/ARCHITECTURE.md`（补充 ADR-0005）、`docs/CHANGELOG.md`（新增条目）。
9. **目测验收**：启动开发服务器，在暗色/亮色间切换，逐页检查主界面、移动端、管理后台、认证弹窗、订阅弹窗的显示效果；刷新页面验证持久化；清除 localStorage 后验证系统偏好跟随。
