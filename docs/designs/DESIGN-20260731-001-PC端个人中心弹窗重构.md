# DESIGN-20260731-001 PC端个人中心弹窗重构

> 创建日期：2026-07-31
> 状态：已实施
> 关联需求：重构 PC 端右上角"个人中心"弹窗，采用左菜单+右内容布局，整合账户/订阅/订单

---

## 一、背景

当前 PC 端个人中心弹窗（`DesktopAccountPanel`，内联于 `components/car-mod-studio.tsx` 第 2536–2986 行）采用单面板 + 顶部 Tab 切换的布局，包含概览/资料/密码/手机号/订单五个 Tab。该布局信息密度高、交互层级扁平，但与用户期望的"左侧菜单 + 右侧内容区"分栏式设置弹窗体验不符。

参考原型 `E:\AI-project\demo2`（Next.js + Tailwind 参考Demo）提供了经典的设置弹窗骨架：左侧 240px 固定菜单 + 右侧内容区，弹窗圆角 16px、按钮圆角 8px。但 demo2 仅为静态展示原型，无编辑/保存/验证码/支付等真实交互。

同时，主界面右上角存在独立的"会员"按钮（`car-mod-studio.tsx:1710`），与"个人中心"按钮并列，功能入口分散。用户希望将订阅内容整合进个人中心弹窗，移除独立的"会员"按钮。

本方案将 PC 端个人中心弹窗重构为分栏式布局，整合账户、订阅、订单三大模块，并复用已有的前后端能力（资料更新、密码修改、手机换绑、头像预设、订单查询、套餐支付）。

## 二、功能描述

### 2.1 用户故事

- 作为已登录用户，我希望点击右上角"个人中心"后，弹出一个左侧菜单（账户/订阅/订单）+ 右侧内容区的设置弹窗，方便我集中管理账户信息。
- 在"账户"页，我希望点击头像弹出小弹窗选择预设头像，直接编辑昵称/邮箱并逐字段保存，通过验证码修改手机号，点击"更改密码"弹出密码修改弹窗。
- 在"订阅"页，我希望看到当前会员额度信息，并能在与 demo2 风格一致的套餐卡片中选择/开通方案。
- 在"订单"页，我希望查看我的订单记录。
- 主界面不再需要独立的"会员"按钮，订阅入口统一收归个人中心。

### 2.2 输入输出

- **输入**：当前登录用户信息（`AuthUser`）、订阅状态（`EntitlementStatus`）、套餐列表（`GET /api/billing/plans`）、订单列表（`GET /api/billing/orders`）、头像预设（`GET /api/account/avatar-presets`）。
- **输出**：资料更新（`PATCH /api/auth/me`）、密码修改（`POST /api/auth/password`）、手机换绑（`POST /api/auth/send-code` + `POST /api/auth/phone`）、套餐开通（`POST /api/billing/checkout` + `POST /api/billing/mock-paid`）。

### 2.3 非功能需求

- 保持当前黑色主题配色（使用 CSS 变量），不引入亮色切换。
- 页面布局结构与按钮风格（圆角、尺寸）尽量与 demo2 一致：弹窗圆角 16px、按钮/输入框圆角 8px、左菜单 240px、内容区内边距 32px。
- 弹窗及子弹窗使用 `createPortal` + framer-motion 动画，遵循 `docs/AGENTS.md` UI 约束。
- 颜色禁止硬编码，须引用 CSS 变量（`0` 与 `auto` 例外）。

## 三、技术实现思路

### 3.1 整体布局结构（参考 demo2，适配黑色主题）

弹窗主体采用横向两栏 flex 布局：

- **遮罩层**：全屏 `fixed inset-0`，背景 `rgba(3,4,6,0.72)` + `backdrop-filter: blur(18px)`（沿用现有遮罩风格），`z-index: 120`，居中 flex。
- **弹窗主体**：`width: min(900px, calc(100vw - 48px))`，`max-height: 90vh`，`border-radius: 16px`（对齐 demo2 的 `rounded-2xl`），`display: flex; flex-direction: row; overflow: hidden`，背景沿用现有深色渐变 `linear-gradient(145deg, rgba(26,28,33,0.98), rgba(8,9,11,0.98))`，边框 `1px solid var(--line-soft)`。
- **左侧菜单**：`width: 240px; flex-shrink: 0`，右边框 `1px solid var(--line-soft)`，内边距 20px，`overflow-y: auto`，`display: flex; flex-direction: column`。三个菜单项：账户（`User` 图标）、订阅（`BadgeCheck` 图标）、订单（`Receipt` 图标）。菜单项按钮：`width: 100%; padding: 8px 12px; border-radius: 8px; font-size: 14px`，选中态背景 `rgba(255,255,255,0.08)` + 白色文字，未选中态 `var(--muted)` 文字 + hover `rgba(255,255,255,0.04)` 背景。图标 16px，`margin-right: 12px`。
- **右侧内容区**：`flex: 1; padding: 32px; overflow-y: auto; position: relative`。右上角关闭按钮：绝对定位 `top: 24px; right: 24px`，`X` 图标 24px，`color: var(--muted); hover: var(--text)`。通过 `activeMenu` 状态条件渲染三个内容页。

### 3.2 组件架构

将原本内联的 `DesktopAccountPanel` 抽取为独立组件文件，降低 `car-mod-studio.tsx` 复杂度：

- **新增** `components/pc-account-panel.tsx`：PC 端个人中心弹窗主组件，承载左菜单 + 右内容区 + 子弹窗编排。
  - Props：`user: AuthUser`、`billing: EntitlementStatus | null`、`onClose: () => void`、`onUpdatedUser: (u: Partial<AuthUser>) => void`、`onUpdatedBilling: (b: EntitlementStatus) => void`、`onLogout: () => void`（按需）。
  - 内部状态：`activeMenu: "account" | "subscribe" | "orders"`、`avatarPickerOpen: boolean`、`passwordPopupOpen: boolean`。
  - 子区块（同文件内函数组件或区块渲染函数）：
    - `AccountSection`：账户页内容。
    - `SubscribeSection`：订阅页内容。
    - `OrdersSection`：订单页内容。
    - `AvatarPickerPopup`：头像选择子弹窗。
    - `PasswordChangePopup`：密码修改子弹窗。

- **修改** `components/car-mod-studio.tsx`：
  - 移除内联的 `DesktopAccountPanel` 实现（第 2536–2986 行）。
  - 引入 `PcAccountPanel` 组件，保留 `profileOpen` state 与渲染挂载点（第 2498–2517 行区域），传入所需 props。
  - **移除** Header 中的"会员"按钮（第 1710 行附近），仅保留"个人中心"按钮。
  - 移除弹窗 Hero 区与概览页中对 `onSubscribe` 的调用（订阅入口改为菜单内）。

### 3.3 账户页（AccountSection）

布局参考 demo2 账户信息页，容器最大宽度约 480px（`max-width: 36rem`），垂直排列：

1. **标题**："账户信息"，`font-size: 18px; font-weight: 700; margin-bottom: 24px`。

2. **头像区**：
   - 64×64px 圆角方块（`border-radius: 8px`），使用 `AccountAvatar` 组件渲染当前头像。
   - 点击头像 → 打开 `AvatarPickerPopup` 子弹窗。
   - 头像下方可加一行小字提示"点击更换头像"。

3. **昵称字段**（行内编辑 + 保存）：
   - 标签"昵称"（`font-size: 12px; color: var(--muted)`）。
   - 输入框 + 右侧"保存"按钮水平排列。输入框 `border-radius: 8px`，背景 `var(--surface-2)`，内边距 `8px 12px`。
   - 保存按钮默认 `disabled`（灰态），当输入值与当前用户 `name` 不同时变为可用（强调色背景）。点击调用 `updateAccountProfile({ name })`，成功后 `onUpdatedUser` 更新父级状态并重置 disabled。
   - 输入框初始值为当前 `user.name`，编辑时实时比较决定按钮状态。

4. **邮箱字段**：结构与昵称一致，字段为 `email`，保存调用 `updateAccountProfile({ email })`。可加基础邮箱格式校验。

5. **分割线**：`1px solid var(--line-soft); margin: 32px 0`。

6. **手机号区**（验证码换绑）：
   - 标签"手机号"。
   - 手机号输入框 + "发送验证码"按钮（带 60s 倒计时冷却，参考 `auth-modal.tsx` 的 `codeCooldown` 实现，补齐当前 PC 端缺失的冷却逻辑）。
   - 验证码输入框 + "确认换绑"按钮。
   - 调用 `sendPhoneChangeCode(phone)` 发送，`changeAccountPhone({ phone, code })` 换绑。

7. **密码区**：
   - 小标题"密码与安全"。
   - "更改密码"按钮（圆角 8px，强调色背景），点击 → 打开 `PasswordChangePopup` 子弹窗。

### 3.4 头像选择子弹窗（AvatarPickerPopup）

- 通过 `createPortal` 渲染，遮罩较主弹窗更深（`rgba(0,0,0,0.5)` + blur）。
- 小弹窗居中，宽度约 360px，`border-radius: 16px`，深色背景。
- 标题"选择头像" + 关闭按钮。
- 预设头像网格（`display: grid; grid-template-columns: repeat(4, 1fr); gap: 12px`），每项 56×56px 圆角方块，选中态加边框高亮。
- 数据来自 `listAccountAvatarPresets()`（弹窗打开时加载，主弹窗已有加载逻辑可复用）。
- 点击某预设 → 调用 `updateAccountProfile({ avatarId })` → 成功后 `onUpdatedUser` 更新头像并关闭子弹窗。

### 3.5 密码修改子弹窗（PasswordChangePopup）

- 通过 `createPortal` 渲染，居中小弹窗，宽度约 400px，`border-radius: 16px`。
- 标题"更改密码" + 关闭按钮。
- 三个字段：当前密码、新密码、确认新密码，均为密码输入框，圆角 8px。
- **未设置密码提示**：当 `user.hasPassword === false` 时，"当前密码"字段下方显示提示文字"未设置密码，该项为空即可"，且该字段可留空。
- **已设置密码**：当前密码字段必填，校验通过后端 `changeUserPassword`。
- 新密码与确认密码须一致，前端校验。
- 提交按钮"确认修改"，调用 `changeAccountPassword({ currentPassword, nextPassword })`，成功后提示并关闭子弹窗。

### 3.6 订阅页（SubscribeSection）

用户确认：额度信息放订阅页顶部；订阅页布局重新设计以匹配 demo2 风格（非直接嵌入现有 SubscribeModal）。

1. **顶部额度信息卡**：
   - 横向排列三张卡片（沿用现有 `account-quota-grid` 思路但重新布局）：当前会员、配置额度、对话额度。
   - 卡片圆角 8px，背景 `var(--surface-2)`，内边距 16px。
   - 数据来自 `billing`（`EntitlementStatus`）：`billing.plan`、`billing.configUsed/configRemaining`、`billing.chatUsedToday/chatRemainingToday`。

2. **套餐选择区**（重新设计，demo2 风格）：
   - 标题"选择会员方案" + 副标题。
   - 套餐卡片：数据来自 `GET /api/billing/plans`（订阅页激活时懒加载），按 free→pro→max 排序。
   - 卡片布局参考 demo2 的卡片风格但适配黑色主题：圆角 8px，背景 `var(--surface)`，边框 `1px solid var(--line-soft)`；`pro` 套餐标记"推荐"角标。
   - 每张卡片：套餐名、价格（`¥X/月`）、功能特性列表（`Check` 图标）、操作按钮。
   - 按钮逻辑沿用现有 `subscribe-modal.tsx`：free→"保留"、付费→"开通"、付费转 free→"到期后回到免费版"、`userCheckoutDisabled`→"联系管理员"。

3. **支付流程子弹窗**：
   - 点击付费套餐 → 弹出支付方式选择子弹窗（`createPortal`），结构沿用现有 `payment-template-modal`：微信/支付宝选择 + "继续支付"按钮。
   - 调用 `POST /api/billing/checkout` + `POST /api/billing/mock-paid`，成功后 `onUpdatedBilling` 更新额度、刷新消息。
   - 支付逻辑（`completeCheckout`）与现有 `subscribe-modal.tsx` 相同，抽取为共享 hook 避免重复（见 3.8）。

### 3.7 订单页（OrdersSection）

- 复用现有订单加载逻辑（`getAccountOrders`），订单页激活时懒加载（沿用 `ordersLoaded` 防重复）。
- 订单表格沿用现有 `account-orders-table` 结构：订单号、套餐、金额、支付方式、状态、创建时间。
- 表格样式适配新容器：圆角 8px，表头背景 `var(--surface-2)`，行间分隔 `var(--line-soft)`。
- 保留空态/加载态/错误态处理。

### 3.8 共享逻辑抽取

现有 `subscribe-modal.tsx` 中的套餐数据获取与支付完成逻辑（`completeCheckout`、`planFeatures`、`planDisplayName`、`visiblePlans` 排序）在 PC 订阅页与移动端订阅页均需使用。为避免重复：

- **新增** `lib/use-subscription-plans.ts`：自定义 hook，封装 `GET /api/billing/plans` 请求与排序逻辑，返回 `{ plans, loading, error }`。
- **新增** `lib/subscription-checkout.ts`：纯函数模块，封装 `completeCheckout(plan, method, cycle)` 调用 `checkout` + `mock-paid` 两步 API 的逻辑，返回 `{ billing }`。
- **新增** `lib/subscription-display.ts`：抽取 `planDisplayName`、`planFeatures` 等展示辅助函数（从 subscribe-modal.tsx 迁移）。
- `subscribe-modal.tsx` 改为从上述模块导入，减少自身代码量；移动端逻辑不受影响。

> 此抽取为推荐项，若评估风险过高可暂时在 `pc-account-panel.tsx` 内联实现相同逻辑，后续再统一抽取。

### 3.9 后端改动：密码设置状态检测

当前系统无法在前端判断用户是否已设置密码，需后端支持：

1. **`lib/types.ts`**（AuthUser 类型，第 466–480 行）：新增字段 `hasPassword: boolean`。
2. **`lib/server/db.ts`**（`mapAuthUser` 函数，第 4372–4390 行）：映射时增加 `hasPassword: Boolean(String(row.password_hash || ""))`。`/api/auth/me` 的 GET 直接返回 `currentUser()`，无需改 route.ts 即可自动携带该字段。
3. **`lib/server/db.ts`**（`changeUserPassword` 函数，第 1790–1800 行）：当 `row.password_hash` 为空串时，跳过 `verifyPassword` 校验，允许 `currentPassword` 为空，直接设置新密码（支持首次设置密码场景）。已设置密码时维持原校验逻辑。

### 3.10 主界面"会员"按钮移除

- `car-mod-studio.tsx` 第 1710 行附近的"会员"按钮（`BadgeCheck` 图标 + `t.member` 文案 + `setSubscribeOpen(true)`）整块移除。
- `subscribeOpen` state 若仅由此按钮触发，评估是否仍有其他入口（如移动端）。移动端订阅入口在 `mobile-studio-app.tsx` 内独立管理，不依赖 PC 的 `subscribeOpen`。若 PC 端无其他订阅入口，可移除 `subscribeOpen` state 及 `SubscribeModal` 在 PC 的挂载（移动端 `SubscribeModal` 挂载在 mobile 组件内，不受影响）。
- Header 布局调整：移除会员按钮后，"个人中心"按钮位置与间距相应调整。

### 4.2 数据库变更

无。`users.password_hash` 字段已存在（`TEXT NOT NULL DEFAULT ''`），空串即表示未设置密码，无需 schema 变更。

### 4.3 接口变更

无新增接口。现有接口能力足够：
- `GET /api/auth/me`：返回值自动新增 `hasPassword` 字段（因 AuthUser 类型变更）。
- `POST /api/auth/password`：行为变更——当用户无密码时允许 `currentPassword` 为空。属兼容性增强，不影响已有密码用户的校验逻辑。
