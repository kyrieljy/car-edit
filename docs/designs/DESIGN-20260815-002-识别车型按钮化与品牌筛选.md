# DESIGN-20260815-002：识别车型按钮化与生成记录品牌筛选

## 元信息
- **创建日期**：2026-08-15
- **状态**：已实施（2026-08-15 编码落地完成，tsc + next lint 零告警）
- **关联需求**：将"用户上传图片后自动识别车型"改为"点击按钮后执行识别"；未订阅用户识别需消耗一次生成额度，订阅后可任意使用；每张图片仅识别一次；历史记录加载后只显示结果不显示按钮。后台「生成记录」新增按"品牌"（模型识别结果）筛选。

---

## 1. 背景
当前 `car-mod-studio.tsx` 在 `onFile` 接收到上传文件后立即调用 `recognizeVehicle(file)` 自动发起车型识别（`components/car-mod-studio.tsx:1070`），用户无法主动控制识别时机，也无法感知识别动作本身。业务方希望对"识别车型"这一动作做产品化包装：
- 让识别成为用户主动触发的行为（按钮），提升可控性与预期管理；
- 将识别动作与会员额度体系绑定：未订阅（free，额度有限）用户每次识别消耗一次"生成图片的机会"，已订阅（Pro/Max，`configRemaining === "unlimited"`）用户可任意使用；
- 识别结果需与具体图片绑定（每图一次），历史记录加载后直接展示结果，不再出现按钮；
- 后台运营侧需要按"识别出的品牌"对生成记录做筛选，便于按车型维度分析。

---

## 2. 功能描述

### 2.1 用户端识别按钮化
- **上传前/后**：当前"识别车型"展示区（上传卡片 `upload-tile` / 移动端上传区 / 预览区）在存在 `vehiclePreview` 且尚未识别（`!vehicleNote && !isRecognizingVehicle`）时，渲染为「识别车型」按钮；不再自动发起识别。
- **点击按钮**：调用 `recognizeVehicle(vehicleFile)`。
  - 识别中：展示"正在识别车型..."（沿用 `isRecognizingVehicle`）。
  - 识别成功：写入 `vehicleNote`（车型）与 `detectedVehicleBrand`（品牌），按钮消失，区域改为展示识别结果（车型/品牌文本），与现有 `vehicleDisplayName` 逻辑一致。
  - 识别失败（非车辆照片 / 接口错误）：保留按钮可重试，`vehicleRecognitionError` 提示照旧。
- **每图一次**：由于识别成功即写入 `vehicleNote`，按钮随之隐藏，当前图片实例无法再次触发识别。历史记录加载时 `vehicleNote` 已被填充，故只展示结果、不展示按钮（复用现有 `historyTitleForItem` / 加载逻辑即可）。
- **额度绑定（核心规则）**：
  - 未订阅用户（`getBillingStatus(userId).configRemaining !== "unlimited"`）：点击按钮时**消耗一次 config 模式生成额度**（调用 `checkAndConsumeEntitlement(userId, "config")`）。额度不足 → 返回 403，前端弹出订阅弹窗（`setAuthOpen` / `subscribe-modal`）并提示。
  - 已订阅用户（`configRemaining === "unlimited"`）：跳过额度校验，可任意识别。
  - 退款策略（待确认，见第 6 节）：建议"识别成功（图像被确认为车辆）才真正扣减；若接口报错或图像被判定为非车辆，则 `refundEntitlementUsage` 退回本次额度"，避免坏图白白消耗机会。

### 2.2 后台生成记录品牌筛选
- 后台「生成记录分析」（`components/admin/generation-records.tsx`）新增「品牌」筛选输入框，按 `generation_jobs.vehicle_brand` 做 `LIKE` 模糊匹配（与现有「零件类别」文本筛选方式一致）。
- 筛选参数经 `/api/admin/generations` 与 `/api/admin/generations/export` 透传到 `getGenerationList`，并同步进入 CSV 导出。
- 表格新增「品牌」列展示 `vehicle_brand`（可选增强，低风险）。

## 3. 技术实现思路

### 3.1 用户端（不生成代码，仅描述逻辑）
- **取消自动识别**：`components/car-mod-studio.tsx` 的 `onFile`（约 L1055-1071）删除末尾 `void recognizeVehicle(file)` 调用；新增 `onRecognizeVehicle` 处理函数，内部调用 `recognizeVehicle(vehicleFile)`。
- **渲染分支**：在上传卡片与预览区的识别展示位置，依 `vehiclePreview / vehicleNote / isRecognizingVehicle` 三态渲染：无预览→上传提示；有预览且未识别且未在识别中→「识别车型」按钮；识别中→"正在识别车型..."；已识别→结果文本。移动端 `components/mobile/mobile-studio-app.tsx` 通过新增 props（`onRecognizeVehicle`、`isRecognizingVehicle` / `canRecognize`、`recognized = Boolean(vehicleNote)`）镜像同一逻辑。
- **品牌透传**：`recognizeVehicle` 已通过 `extractDetectedVehicleBrand` 维护 `detectedVehicleBrand`。发起生成时（`POST /api/generations`）把 `detectedVehicleBrand` 作为 `vehicleBrand` 字段一并提交，最终落入 `generation_jobs.vehicle_brand`。
- **额度校验（服务端权威）**：识别接口内做订阅判断与额度扣减（见 3.2），前端仅负责 403 时引导订阅；可选在按钮旁展示"本次识别将消耗 1 次生成机会"提示（需读取现有账户/计费态，非强制）。

### 3.2 服务端
- **`app/api/vehicle-recognition/route.ts`**：
  1. `requireUser()` 后取 `getBillingStatus(userId)`；
  2. 若 `configRemaining !== "unlimited"`，调用 `checkAndConsumeEntitlement(userId, "config")`：
     - 不允许 → `403 { error: reason }`，由前端引导订阅；
     - 允许 → 继续；
  3. 调用视觉识别；若识别失败 / 非车辆（按退款策略决定是否 `refundEntitlementUsage` 退回额度）；
  4. 在响应 JSON 中补充 `brand: vehicleRecognition.brand`（当前路由未返回 brand 字段，需补；`recognizeVehicleWithProvider` 已返回 `brand`）。
- **`app/api/generations/route.ts`**：读取 `formData.get("vehicleBrand")` 并传入 `runGenerationWorkflow`。
- **`lib/server/generation-engine.ts`**：`RunGenerationWorkflowInput` 新增 `vehicleBrand?`，透传给 `createGeneration`。
- **`lib/server/db.ts`**：
  - 迁移：为 `generation_jobs` 增加 `vehicle_brand TEXT NOT NULL DEFAULT ''`（纳入现有建表/迁移逻辑，约 L253 处）。
  - `createGeneration`：新增入参 `vehicleBrand?`，INSERT 时写入 `vehicle_brand`。
  - `GenerationListFilter` 新增 `brand?`；`getGenerationList` 依据 `brand` 追加 `g.vehicle_brand LIKE ?` 条件，并在 items 选择中返回 `vehicle_brand`。
- **`app/api/admin/generations/route.ts` 与 `export/route.ts`**：解析并透传 `brand` 参数。
- **`components/admin/generation-records.tsx`**：新增 `brand` 筛选 state、`StyledSelect`/文本输入、拼入 `filterParams` 与 `exportParams`、纳入 reset-page 副作用；新增「品牌」表头/列（可选）。

### 3.3 数据回填说明
历史 `generation_jobs` 无 `vehicle_brand`（默认空串）。品牌筛选对存量记录不会命中；如需覆盖历史，可后续对 `display_vehicle_model` 首令牌做一次性品牌提取回填（可选，非本次必需）。

## 8. 验收标准
- [ ] 上传图片后**不**自动识别，识别区显示「识别车型」按钮。
- [ ] 点击按钮触发识别；识别成功后按钮消失并显示车型/品牌结果；识别失败可重试。
- [ ] 同一上传图片实例仅能被识别一次（按钮在结果出现后不再出现）。
- [ ] 已订阅用户点击识别不消耗生成额度，可任意识别。
- [ ] 未订阅用户点击识别消耗 1 次 config 额度；额度不足时弹出订阅引导且不执行识别。
- [ ] 历史生成记录加载后展示识别结果，不显示识别按钮。
- [ ] 后台「生成记录」可按品牌（模型识别结果）筛选，且筛选结果与 CSV 导出一致。
- [ ] 相关文档（API_REFERENCE / DB_SCHEMA / CHANGELOG 等）同步更新。
