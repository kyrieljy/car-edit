# DESIGN-20260726-008：移动端改图菜单模式切换隔离

## 元信息
- **创建日期**：2026-07-26
- **状态**：已实施
- **关联需求**：手机端仅"改图"菜单下显示"配置模式/对话模式"切换；切换到生图、视频、特效菜单时仅显示"即将上线"字样

---

## 1. 背景

移动端应用菜单导航系统（DESIGN-20260725-003）已落地四个子菜单（改图、生图、视频、特效）与 `activeMenu` 状态，并实现了"即将上线"占位（`mobile-coming-soon`，已用 `activeMenu !== "edit"` 正确条件渲染）。PC 端（`car-mod-studio.tsx`）也已正确隔离——非"改图"菜单时工作区渲染为 `null` 且显示 `app-coming-soon`。

但移动端存在一处遗漏：`MobileModeSwitch`（配置模式/对话模式切换栏，位于 `mobile-shared-mode-bar` 容器）与 `MobileAccessBanner`（登录/额度提示层）均为**无条件渲染**，未与 `activeMenu` 联动。这导致用户从"改图"切换到"生图/视频/特效"时，顶部的"配置模式/对话模式"切换栏仍然悬浮显示，与"即将上线"占位同时出现，违反"其他菜单仅显示即将上线"的预期，且残留的 config/chat 额度提示在非改图菜单下造成信息错位。

本次需求即在移动端将模式切换栏与访问提示层隔离到"改图"菜单下，使非改图菜单呈现纯净的"即将上线"占位。

## 2. 功能描述

### 2.1 改图菜单（activeMenu === "edit"）

- 保持现状：顶部显示"配置模式/对话模式"切换栏（`MobileModeSwitch`），下方渲染当前模式（`MobileConfigMode` 或 `MobileChatMode`）的内容。
- 登录/额度提示（`MobileAccessBanner`）按现有逻辑在需要时显示。

### 2.2 其他菜单（生图 / 视频 / 特效，activeMenu !== "edit"）

- **隐藏**"配置模式/对话模式"切换栏（`mobile-shared-mode-bar`）。
- **隐藏**登录/额度提示层（`mobile-access-banner-layer`），因其仅服务于 config/chat 模式，在"即将上线"场景下无意义且易误导。
- **仅显示**"即将上线"占位（`mobile-coming-soon`），作为该菜单下唯一可见的主内容，居中呈现。

### 2.3 切换行为

- 用户在菜单抽屉（`MobileMenuDrawer`）中点击"改图"→ 显示模式切换栏 + 模式内容（`appMode` 保持原值，自动恢复上次所在模式）。
- 用户点击"生图/视频/特效"→ 关闭抽屉 → 隐藏模式切换栏与访问提示层 → 仅显示"即将上线"。
- 在非改图菜单下，`appMode` 状态保持不变（不重置），以便切回改图时无缝恢复。

### 2.4 非功能性要求

- 主题适配：占位与隐藏逻辑不引入新的硬编码颜色，"即将上线"文案继续使用 `--muted` + `--font-mono`，暗色/亮色模式下均正常。
- 仅移动端变更，PC 端不在本次范围内（PC 已正确隔离）。

## 3. 技术实现思路

### 3.1 整体策略

核心为渲染条件收窄：将 `mobile-shared-mode-bar` 与 `mobile-access-banner-layer` 两个块的渲染从无条件改为 `activeMenu === "edit"` 守卫。无需新增状态或数据流，`activeMenu` 已是顶层 state。

### 3.2 模式切换栏隔离

`MobileStudioApp` 主 return 中（约第 695-697 行），`<div className="mobile-shared-mode-bar">` 内的 `MobileModeSwitch` 当前无条件渲染。改为以 `activeMenu === "edit" && (...)` 包裹，使该栏仅在改图菜单下出现。

由于该栏为 `position: absolute`（脱离文档流），隐藏它不会引起主内容区布局抖动。`MobileConfigMode`/`MobileChatMode` 内部的 `mobile-shared-mode-spacer`（为浮动栏预留空间的占位元素）仅在 `activeMenu === "edit"` 时随模式内容一同渲染，故无冲突。

### 3.3 访问提示层隔离

`mobile-access-banner-layer`（约第 698-711 行）内的 `MobileAccessBanner` 同样以 `activeMenu === "edit"` 守卫。`accessKind` 派生自 `appMode`，在非改图菜单下 `appMode` 虽未变但已不展示对应模式内容，故其额度/登录提示不应出现。

### 3.4 "即将上线"占位呈现

当前 `mobile-coming-soon` 为 `min-height: 40vh` 的居中 flex 容器，已满足"仅显示文字"的基本要求。本次保持其结构，仅在 `activeMenu !== "edit"` 时它成为 `mobile-studio-phone` 区段内唯一子节点（模式切换栏与提示层已隐藏），自然居中。可选微调：将其 `min-height` 提升为占满主可视区（如 `min-height: 60vh` 或基于 `calc` 撑满），使"即将上线"在更大区域内居中，视觉更聚焦。该微调为可选项，由编码阶段视效果决定。

### 3.5 与现有模块的交互

- `MobileMenuDrawer` 的 `onSelect` 回调已正确设置 `activeMenu`（第 744-747 行），无需改动。
- `appMode` 状态在菜单切换间保持，切回改图时模式内容按原 `appMode` 渲染，无额外处理。
- PC 端 `car-mod-studio.tsx` 已正确隔离，不修改。

## 7. 实施步骤

1. **隔离模式切换栏**：在 `mobile-studio-app.tsx` 的 `MobileStudioApp` 主 return 中，将 `mobile-shared-mode-bar` 块以 `activeMenu === "edit" && (...)` 包裹。
2. **隔离访问提示层**：将 `mobile-access-banner-layer` 块（含 `MobileAccessBanner`）同样以 `activeMenu === "edit" && (...)` 包裹。
3. **占位呈现微调（可选）**：在 `globals.css` 中视效果调整 `.mobile-coming-soon` 的 `min-height`，使"即将上线"在非改图菜单下居中更聚焦。
4. **回归验证**：改图菜单下模式切换栏、模式内容、访问提示均正常；切换到生图/视频/特效后仅显示"即将上线"，无切换栏与提示层残留；切回改图后模式与提示恢复正常；暗色/亮色模式下均正常。
