# DESIGN-20260806-006：公网域名配置管理

## 元信息
- **创建日期**：2026-08-06
- **状态**：已实施
- **关联需求**：管理后台新增"域名配置"菜单，编辑 PUBLIC_ASSET_BASE_URL，调用生图 API 时用此域名拼接图片链接

---

## 1. 背景

当前系统调用 Nano-Banana / Gemini 等需要公网图片 URL 的生图 Provider 时，公网域名从环境变量按优先级读取：`PROVIDER_PUBLIC_BASE_URL` → `NEXT_PUBLIC_APP_URL` → `APP_URL` → `SITE_URL`（见 `lib/server/generation-provider.ts` 的 `providerInputPublicBaseUrl()` 函数）。

存在的问题：
- 修改域名需要重启服务（环境变量不可热更新）
- 无法在管理后台直观查看和修改当前生效的公网域名
- 管理员需要通过 SSH/服务器面板修改 `.env` 文件，操作门槛高

需求目标：将公网域名配置从环境变量迁移到数据库管理，管理员可在后台直接编辑，保存后立即生效（下次生图调用即使用新域名），无需重启服务。

---

## 2. 功能描述

### 2.1 管理后台域名配置页面

- 在管理后台"系统配置"分类下新增"域名配置"菜单项
- 页面提供一个文本输入框，管理员可编辑 `PUBLIC_ASSET_BASE_URL`
- 输入框下方展示拼接示例（如 `https://example.com` + `/uploads/vehicle-xxx.jpg` = `https://example.com/uploads/vehicle-xxx.jpg`）
- 保存按钮直接生效，无需审核流程
- 页面展示当前生效的完整示例 URL，方便管理员验证配置是否正确

### 2.2 生图 API 图片链接拼接

- 调用生图 API 需要传入图片 URL 时（Nano-Banana / Gemini 路径），使用数据库中配置的 `PUBLIC_ASSET_BASE_URL` 作为基础域名
- 拼接方式：`PUBLIC_ASSET_BASE_URL` + 图片 API 路径（如 `/uploads/{fileName}`）
- 数据库配置优先于环境变量：若数据库已配置非空值则使用数据库值，否则回退到现有环境变量链路（保证向后兼容）

### 2.3 输入校验

- 必须是合法的 http/https URL
- 拒绝 localhost / 127.0.0.1 / ::1 / 0.0.0.0 等本地地址（与现有 `isLocalOnlyHost` 逻辑一致）
- 自动去除末尾斜杠，避免拼接出双斜杠

---

## 3. 技术实现思路

### 3.1 整体策略

采用与 `guardrail_configs` 完全一致的单行配置表模式：
1. 新建 `site_configs` 表，单行记录（id = 'default'），存储 `public_asset_base_url` 字段
2. 在 `lib/types.ts` 新增 `SiteConfig` 类型
3. 在 `lib/catalog.ts` 新增 `siteConfigSeed` 种子数据（默认空字符串，表示未配置）
4. 在 `lib/server/db.ts` 新增 `getSiteConfig()` / `updateSiteConfig()` 函数
5. 新建 API 路由 `app/api/admin/site-config/route.ts`（GET 读取 / POST 保存）
6. 在 `components/admin-console.tsx` 新增菜单项和 `DomainConfigManager` 面板组件
7. 修改 `lib/server/generation-provider.ts` 的 `providerInputPublicBaseUrl()` 函数，优先读取数据库配置

### 3.2 关键逻辑：providerInputPublicBaseUrl 改造

当前函数是纯函数，仅读环境变量。改造后需要读数据库，因此变为异步函数：

```
改造前（同步）:
function providerInputPublicBaseUrl(): string {
  读环境变量链 → 返回 origin 或 ""
}

改造后（异步）:
async function providerInputPublicBaseUrl(): Promise<string> {
  1. 从数据库读取 site_configs.public_asset_base_url
  2. 若非空且合法（非 localhost）→ 返回该 origin
  3. 否则回退到环境变量链 → 返回 origin 或 ""
}
```

由于该函数变为异步，调用方 `nanoBananaProviderInputImages` / `nanoBananaProviderInputImage` 也需要相应改为 `await`。这些函数本身已经是 `async`，改动量小。

### 3.3 URL 拼接逻辑

沿用现有 `absoluteProviderInputImageUrl(localUrl, publicBaseUrl)` 函数：
```
new URL(localUrl, publicBaseUrl).toString()
```
例如：`new URL("/uploads/vehicle-xxx.jpg", "https://example.com").toString()` → `https://example.com/uploads/vehicle-xxx.jpg`

无需修改此函数，仅需确保传入的 `publicBaseUrl` 来源正确。

### 3.4 影响范围限定

- 仅影响 Nano-Banana / Gemini 路径（通过 `providerUrl` 字段传入 JSON payload 的 `image_urls`）
- OpenAI 兼容 `images/edits` 路径发送二进制数据，不传 URL，不受影响
- 视觉检查 Provider（`vision-provider.ts`）的图片 URL 不经过此函数，不受影响

## 6. 风险与应对

| 风险 | 可能性（高/中/低） | 影响（高/中/低） | 应对措施 |
|------|--------------------|--------------------|----------|
| `providerInputPublicBaseUrl` 异步化导致遗漏 await | 低 | 中 | 该函数仅在 `nanoBananaProviderInputImages` / `nanoBananaProviderInputImage` 中调用，两处均已是 async 函数，改动范围可控；编码后通过 TypeScript 编译验证 |
| 管理员配置了错误的域名导致生图失败 | 中 | 中 | 前端保存时校验 URL 格式和 localhost；后端同样校验；页面展示拼接示例供管理员验证 |
| 数据库迁移失败（表已存在等） | 低 | 低 | 使用 `CREATE TABLE IF NOT EXISTS`，与现有表创建模式一致 |
| 向后兼容：数据库未配置时回退环境变量 | 低 | 低 | `getSiteConfig()` 返回空字符串时，`providerInputPublicBaseUrl` 自动回退到环境变量链路 |
