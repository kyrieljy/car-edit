# DESIGN-20260725-002：生成图对比样式重构为重叠滑块

## 元信息
- **创建日期**：2026-07-25
- **状态**：已实施
- **关联需求**：将生成图片后的对比样式由“并排/堆叠双图”改为“原图与生成图同一位置重叠、拖动中间手柄控制显示比例”，参考 `demo/compare.txt`

---

## 1. 背景

当前“对比”视图（`viewMode === "compare"`）采用双格网格：桌面端为左右两列（`compare-grid`），移动端为上下两行（`mobile-compare-grid`），分别展示原图与生成图。该方式需要用户视线在两张图之间来回跳动，难以聚焦同一区域的细微差异。

`demo/compare.txt` 提供了一种更直观的“图像对比滑块”交互：两张图重叠在同一位置，通过拖动中间的竖向手柄，用 `clip-path` 控制两侧各显示多少。这种交互在改装前后对比场景下能显著提升观察效率。

本次需求将该滑块交互落地到生产代码，同时遵循项目的纯 CSS / lucide-react / 设计令牌约束（`demo/compare.txt` 使用了 Tailwind 与内联 SVG，均被项目禁止，需改写）。

## 2. 功能描述

- **核心用例**：用户生成改装图后，切换到“对比”视图，原图与生成图重叠在同一画框内；用户拖动画框中间的竖向手柄，左侧显示原图、右侧显示生成图（或反之），手柄位置决定两侧可见比例。
- **输入**：原图 URL（`vehiclePreview`）、生成图 URL（`job.resultImageUrl`）。
- **输出/预期行为**：
  - 桌面端与移动端均采用同一套重叠滑块组件。
  - 手柄支持鼠标拖动与触摸拖动；拖动过程中实时更新两侧可见区域，无卡顿。
  - 移动端拖动时不得触发页面上下滚动。
  - 滑块上不显示任何文字标签（如“原图/生成图/Before/After”）。
  - 对比模式下点击“保存/导出”时，仅下载生成图本身（与“生成图”视图导出行为一致），不再合成对比图。
- **非功能性需求**：遵循 `docs/AGENTS.md` 的 UI 约束——纯 CSS（`globals.css`）、lucide-react 图标、framer-motion 动画、禁止 Tailwind / 内联 SVG / 硬编码颜色与像素值（动态滑块位置的 `clip-path` 与 `left` 属运行时动态值，不属设计令牌覆盖，与现有 `--paint` 内联变量用法一致）。

## 3. 技术实现思路

### 3.1 新增可复用滑块组件

新建 `components/image-comparison-slider.tsx`，导出一个 `ImageComparisonSlider` 组件，供桌面端与移动端共用，避免重复实现。

- **Props**：`beforeSrc`（原图 URL）、`afterSrc`（生成图 URL）、可选 `altBefore` / `altAfter` / `initialPosition`（默认 50）/ `className`。
- **状态**：`sliderPosition`（0–100）、`isDragging`。
- **引用**：`containerRef` 指向滑块外层容器，用于计算拖动百分比。
- **图层结构**：
  - 底层（满铺）：生成图（`afterSrc`）。
  - 顶层（裁剪）：原图（`beforeSrc`），通过 `clipPath: inset(0 calc(100% - position%) 0 0)` 只显示左侧 `position%` 区域；右侧露出底层生成图。最终效果：左侧原图、右侧生成图，手柄位于 `position%` 处。
  - 两层图片均使用 `object-fit: contain`、`width/height: 100%`、绝对定位 `inset: 0`，确保两图占据完全相同的盒子，裁剪边界对齐。
- **拖动逻辑**：统一使用指针事件（`onPointerDown` / `onPointerMove` / `onPointerUp`）兼容鼠标与触摸；在 `pointerdown` 时置 `isDragging=true` 并捕获指针，`pointermove` 时根据 `clientX` 相对容器左侧的比例计算新位置并 clamp 到 0–100；在 `window` 上监听 `pointerup` 以保证指针离开容器后仍能结束拖动。
- **手柄**：竖向分隔线 + 圆形握把，握把内放一个 lucide-react 图标（如 `ChevronsLeftRight`），拖动时握把轻微放大反馈（可用 framer-motion 或 CSS transition）。
- **触摸防滚动**：容器与手柄设置 `touch-action: none`，防止拖动时页面滚动。
- **可访问性**：手柄节点设 `role="slider"`、`aria-valuenow/min/max`、`aria-label`，并支持左右方向键以 1% / 10% 步进调整，满足键盘用户使用。
- **样式来源**：所有视觉样式通过 `globals.css` 中的新 CSS 类实现，颜色/阴影引用设计令牌（如 `var(--accent)`、`var(--bg)`、`var(--line)`、`var(--shadow)`），仅在 `clip-path` 与 `left` 上使用内联动态值。

### 3.2 桌面端接入

在 `components/car-mod-studio.tsx` 的对比视图分支中，用 `ImageComparisonSlider` 替换现有 `compare-grid` 双格结构：

- 当存在生成图时，渲染 `<ImageComparisonSlider beforeSrc={safeVehiclePreview} afterSrc={safeGeneratedResultUrl} />`。
- 当无生成图时（极端兜底），沿用现有 `GeneratedPreview` 兜底渲染，保持行为不变。

### 3.3 移动端接入

在 `components/mobile/mobile-studio-app.tsx` 的 `isCompareView` 分支中，用同一 `ImageComparisonSlider` 替换 `mobile-compare-grid` 双图结构。移动端进入对比视图已要求 `hasGenerated` 为真，故两图 URL 均可用。

### 3.4 导出行为调整

`saveResult` 当前在 `exportMode === "compare"` 时调用 `downloadCompareImage` 合成上下堆叠图。根据需求，对比模式仅导出生成图：

- 将对比分支改为与“生成图”分支一致，调用 `downloadImageAsset(job.resultImageUrl, ...)` 下载生成图，文件名沿用 `ai-mod-result-${job.id}${扩展名}`。
- 由于 `downloadCompareImage` 不再被任何地方引用，从 `lib/client/image-download.ts` 中移除该函数及其仅被它使用的私有辅助函数（`loadImageElement`、`imageAspectRatio`、`drawContainedImage`、`canvasToBlob`），并从 `car-mod-studio.tsx` 的 import 中移除 `downloadCompareImage`。
- 桌面端与移动端的保存按钮调用 `saveResult(...)` 入口不变，内部行为统一由 `saveResult` 处理。

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 两图宽高比不同时，`object-fit: contain` 留白导致裁剪边界与主体错位 | 中 | 中 | 两层使用完全相同的盒模型与 `object-fit`，裁剪按容器百分比计算，主体对齐；如实测错位明显，后续可加默认 `object-position` 统一 |
| 移动端拖动与页面滚动冲突 | 中 | 高 | 容器与手柄设 `touch-action: none`，并在 `pointerdown` 捕获指针 |
| 频繁 `pointermove` 触发渲染抖动 | 低 | 低 | 单滑块场景 setState 开销可忽略；必要时用 `requestAnimationFrame` 节流 |
| 删除 `downloadCompareImage` 误伤其他引用 | 低 | 中 | 已全仓库检索确认仅 `car-mod-studio.tsx` 引用；删除后运行 lint 与冒烟测试验证 |
| 键盘用户无法拖动 | 中 | 中 | 手柄设 `role="slider"` 并支持方向键步进 |
