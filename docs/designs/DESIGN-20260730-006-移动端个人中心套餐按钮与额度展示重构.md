# DESIGN-20260730-006：移动端个人中心套餐按钮与额度展示重构

## 元信息
- **创建日期**：2026-07-30
- **状态**：已实施
- **关联需求**：重构移动端个人中心卡片区域按钮：将头部"编辑资料"按钮改为显示当前套餐名称（小写 id）并点击进入订阅界面；将下方两个操作按钮改为分别只读展示生成额度与对话额度

---

## 1. 背景

本方案为 `DESIGN-20260730-005`（已实施）的后续调整。经 -005 调整后，移动端个人中心（`MobileProfilePage` 组件）overview 主页面卡片区域当前状态为：

- **卡片头部**：头像 + 昵称 + "编辑资料"按钮（触发 `openProfileSection("profile")` 进入资料编辑子页面）
- **卡片操作区**（`mobile-profile-card-actions`）两个按钮：
  - 左按钮：`Sparkles` 图标 + `planName`（套餐 label，如 Free/Pro/Max）→ 触发 `openSubscribe`
  - 右按钮：`Zap` 图标 + 合并文本"生成 X · 对话 Y" → 触发 `openSubscribe`

用户希望进一步优化首屏信息层级：将套餐名称提升至卡片头部显眼位置（替换"编辑资料"文字按钮）作为进入订阅套餐界面的入口；下方两个操作按钮不再承担跳转职责，改为分别只读展示生成额度与对话额度，点击无任何效果。

## 2. 功能描述

### 核心变更

对 `MobileProfilePage` 组件 overview 主页面卡片区域做两处调整：头部按钮套餐化、操作按钮额度化只读化。

### 具体功能点

1. **头部"编辑资料"按钮 → 套餐名称按钮**
   - 原文案：「编辑资料」/「Profile」
   - 新文案：显示当前用户的套餐名称，采用**小写 id**格式（`free` / `pro` / `max`），与用户需求示例一致
   - 数据来源：新增局部变量 `planIdDisplay`，取值优先级 `billing?.plan.id || authUser?.plan || (isZh ? "游客" : "guest")`
     - `billing.plan.id` 类型为 `MembershipPlanId`（"free" | "pro" | "max"）
     - `authUser.plan` 类型为 `MembershipPlanId | "internal" | "prototype"`，普通用户即为 free/pro/max
     - 未登录时回退为"游客"/"guest"
   - 点击行为：由 `openProfileSection("profile")` 改为 `openSubscribe`（打开订阅弹窗，即"订阅套餐界面"）
   - 图标：当前按钮无图标，保持无图标纯文本样式
   - 未登录分支：保持现有"登录"/"Sign in"按钮（触发 `openAuth`）不变

2. **操作区两个按钮 → 分别只读展示生成额度与对话额度**
   - **左按钮（原套餐按钮）**：
     - 新文案：生成剩余额度，格式 `生成 {configBalance}` / `Gen {configBalance}`
     - 数据来源：复用已有 `configBalance` 变量（`billing.configRemaining` 经 `formatMobileProfileBalance` 格式化，unlimited 显示"不限"/"Unlimited"，billing 为 null 时显示"--"）
     - 图标：保留 `Sparkles`
     - 点击行为：移除 `onClick`，仅展示，点击无效果
   - **右按钮（原合并额度按钮）**：
     - 新文案：对话剩余额度，格式 `对话 {chatBalance}` / `Chat {chatBalance}`
     - 数据来源：复用已有 `chatBalance` 变量（`billing.chatRemainingToday` 经 `formatMobileProfileBalance` 格式化，规则同上）
     - 图标：保留 `Zap`
     - 点击行为：移除 `onClick`，仅展示，点击无效果
   - 两个按钮文案由合并变为拆分，单按钮文案变短，溢出风险降低

### 编辑资料入口影响

头部"编辑资料"按钮被替换后，资料编辑子页面（`openProfileSection("profile")`）仍可通过**点击头像**访问（卡片头部头像已有 `onClick={() => authUser && openProfileSection("profile")}`，-005 保留未动）。本方案不新增额外入口，依赖头像点击作为编辑资料的唯一入口。

### 非功能需求

- 套餐 id 与额度数值实时反映 `billing` 状态，无需额外请求
- 暗色/亮色主题兼容：按钮样式复用现有 CSS 变量与 `.mobile-profile-card-actions button` 规则
- 两个额度按钮变为只读后，需在 CSS 层移除交互态（cursor、hover、active），避免误导用户认为可点击

## 3. 技术实现思路

### 整体策略

仅修改 `MobileProfilePage` 组件的 JSX 渲染逻辑与少量 CSS，不涉及数据层、API、路由变更。`billing`、`configBalance`、`chatBalance`、`formatMobileProfileBalance`、`openSubscribe`、`openAuth` 等变量和函数已在组件作用域内可用，直接复用。

### 关键逻辑

1. **新增套餐 id 展示变量**
   - 在 `planName` 定义附近新增：`planIdDisplay = billing?.plan.id || authUser?.plan || (isZh ? "游客" : "guest")`
   - 取 `billing.plan.id`（MembershipPlan.id 字段）而非 `plan.label`，确保小写 id 格式

2. **头部按钮改造**
   - `authUser` 分支：文案节点由 `{isZh ? "编辑资料" : "Profile"}` 替换为 `{planIdDisplay}`，`onClick` 由 `openProfileSection("profile")` 改为 `openSubscribe`
   - 未登录分支保持"登录"按钮不变

3. **操作区按钮只读化**
   - 左按钮：文案节点由 `{planName}` 替换为 ``{isZh ? `生成 ${configBalance}` : `Gen ${configBalance}`}``，移除 `onClick={openSubscribe}`
   - 右按钮：文案节点由合并文本替换为 ``{isZh ? `对话 ${chatBalance}` : `Chat ${chatBalance}`}``，移除 `onClick={openSubscribe}`
   - 两按钮保留现有 `Sparkles` / `Zap` 图标

4. **清理未使用变量**
   - 改造后 `planName`（label 形式）在 `MobileProfilePage` 中不再被引用，需删除该变量定义，避免未使用变量告警/编译错误（若 tsconfig 启用 `noUnusedLocals`）
   - `LegacyMobileProfilePage` 中的 `planName` 为独立作用域，不受影响，不修改

### CSS 调整

- 在 `.mobile-profile-card-actions button` 规则中移除交互态样式：
  - 移除 `cursor: pointer`（改为 `cursor: default`）
  - 移除 hover / active 态的视觉变化（如 transform、背景色变化等）
  - 保留布局、字号、颜色等展示样式
- 由于两个按钮文案由合并长文本变为单值短文本（如"生成 5"），溢出风险降低，-005 新增的 `white-space: nowrap` / `min-width: 0` 可保留，无需进一步调整
- 本次仅移除交互态，不涉及颜色变更，无需在 `[data-theme="light"]` 作用域内新增亮色规则

### 与现有模块的交互

- `openSubscribe`：已有函数（设置 `setSubscribeOpen(true)`），由头部套餐按钮触发，无需修改
- `openAuth`：已有函数，未登录分支复用，无需修改
- `openProfileSection("profile")`：仍由头像 `onClick` 触发，编辑资料入口保留
- `formatMobileProfileBalance`：已有函数，处理 `"unlimited"` → 文字转换，无需修改
- `LegacyMobileProfilePage`：未被任何组件引用，不修改
