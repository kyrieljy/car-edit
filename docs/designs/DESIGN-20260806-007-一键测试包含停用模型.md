# DESIGN-20260806-007：一键测试所有模型支持停用模型并行测试

## 元信息
- **创建日期**：2026-08-06
- **状态**：已实施
- **关联需求**：将管理员界面"模型 API"菜单中"一键测试所有模型"按钮的效果改为"无论模型是否启用，均需要并行测试"。
- **关联方案**：DESIGN-20260806-004（原始一键测试功能，已实施）

---

## 1. 背景

原始方案 DESIGN-20260806-004 实现了"一键测试所有模型"功能，可并发测试所有 Provider 的连通性和鉴权状态。但当前实现对 `enabled === false`（已停用）的 Provider 直接跳过，标记为"跳过"状态，不发起实际测试请求。

管理员在排查问题时，往往需要验证所有已配置 Provider 的可用性（包括当前处于停用状态的），例如：临时停用的 Provider 是否仍然可用、评估是否可以重新启用。当前的"跳过"行为无法满足此需求。

本次变更将移除"已停用即跳过"的判断，使停用的 Provider 也被纳入并行测试范围。

---

## 2. 功能描述

### 核心用户故事

作为管理员，我在"模型 API"页面点击"一键测试所有模型"按钮后，系统对**所有** Provider（无论启用或停用）发起并行测试请求，弹窗结果中停用的模型同样显示"可用"或"不可用"状态，而非"跳过"。

### 变更前后的行为对比

| 场景 | 变更前 | 变更后 |
|------|--------|--------|
| 启用 + 有 Key | 并行测试 | 并行测试（不变） |
| 启用 + 无 Key | 跳过 | 跳过（不变） |
| **停用 + 有 Key** | **跳过** | **并行测试** |
| 停用 + 无 Key | 跳过 | 跳过（不变） |
| mock/local | 跳过 | 跳过（不变） |

### 不变项

- 测试请求格式、判定标准、超时控制、并发执行方式均不变
- mock/local Provider 仍跳过（无真实端点可测）
- 未配置 API Key 的 Provider 仍跳过（无法构造鉴权请求）
- 结果弹窗表格结构、排序规则不变

---

## 3. 技术实现思路

### 整体策略

仅需移除 `testProvider()` 函数中针对 `!provider.enabled` 的跳过分支。该分支位于 mock/local 跳过之后、API Key 跳过之前，移除后停用且有 Key 的 Provider 将落入正常测试流程。

### 并发执行

当前代码已使用 `Promise.all(providers.map((provider) => testProvider(provider)))` 实现并发。`testProvider` 内部有 try-catch，单个 Provider 测试异常不会导致整体 reject，因此 `Promise.all` 的行为等价于 `Promise.allSettled`。移除 enabled 跳过后，并发量随停用 Provider 数量增加，但因单次超时 15 秒且各 Provider 独立，不会互相阻塞。

### 结果展示

停用的 Provider 测试后将返回"可用"或"不可用"状态，在结果弹窗中正常展示。原"跳过"状态仍保留用于 mock/local 和无 Key 的 Provider，弹窗汇总栏的"跳过"计数会相应减少。

- 停用的 Provider 会被实际调用，但因测试请求为最小化请求（省略图片数据、max_tokens=1），不会产生实际生成费用（文生图端点的极少量费用已在原方案中评估并接受）。
- 测试不修改 Provider 配置数据，为只读操作。

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|---|---|---|---|
| 停用 Provider 中包含文生图端点，测试时产生极少量费用 | 中 | 低 | 使用最小 prompt 和 n=1 控制；测试由管理员手动触发，非自动定时 |
| 并发量增加导致同时请求的服务商增多，触发限流 | 低 | 低 | 限流响应（429）已判定为"可用"；15 秒超时兜底 |
| 停用 Provider 的 Key 已过期或被撤销，测试返回鉴权失败 | 中 | 无 | 正确显示为"不可用"，帮助管理员发现问题，符合预期 |
