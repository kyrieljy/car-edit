# DESIGN-20260725-003：应用菜单导航系统

## 元信息
- **创建日期**：2026-07-25
- **状态**：待审核
- **关联需求**：添加应用菜单（改图、生图、视频、特效），PC端悬浮左侧菜单栏，移动端重构导航入口，历史迁移至用户中心

---

## 1. 背景

当前应用缺乏顶层功能导航，所有功能集中在单一的改图工作室内。随着业务扩展，需要引入"生图"、"视频"、"特效"等新功能模块，因此需要一个统一的菜单系统来组织这些功能入口。同时，移动端的导航结构需要适配——现有的左上角菜单按钮直接打开历史抽屉（config 模式）或聊天侧栏（chat 模式），不够直观，需要重构为功能菜单；历史模块则迁移至用户中心，使导航逻辑更加清晰。

---

## 2. 功能描述

### 2.1 核心功能菜单

四个子菜单项：

| 菜单项 | 图标建议（lucide-react） | 当前状态 | 点击行为 |
|--------|------------------------|---------|---------|
| 改图 | `PencilRuler` 或 `Wrench` | 已有功能 | 进入当前改图工作室（即现有 config 模式） |
| 生图 | `ImagePlus` 或 `Sparkles` | 未开发 | 居中显示"即将上线"占位 |
| 视频 | `Video` 或 `Film` | 未开发 | 居中显示"即将上线"占位 |
| 特效 | `Zap` 或 `Wand2` | 未开发 | 居中显示"即将上线"占位 |

### 2.2 PC端菜单栏

- **位置**：左上角悬浮，紧贴视口左侧边缘
- **样式**：参考 `demo/meum.txt` 的 Tabs 竖排布局
- **交互**：
  - 默认仅显示图标
  - 鼠标悬停时通过 Tooltip（`TooltipContent`，side="right"）显示对应文字标签
  - 当前激活的菜单项有高亮状态（使用品牌色 `--yellow: #614b00` 或 `--yellow-2: #735b00`）
  - 选中"改图"时高亮，选择其他三个菜单项时弹出占位页面，同时菜单项高亮切换
- **主题色适配**：使用全局 CSS 变量（`--yellow`、`--bg`、`--surface`、`--line-soft`、`--muted` 等）保持与暗黑奢华主题一致

### 2.3 移动端菜单

- **左上角菜单按钮行为变更**：
  - 原逻辑：config 模式下打开历史抽屉，chat 模式下打开聊天侧栏
  - 新逻辑：无论 config/chat 模式，均打开全屏抽屉，展示四个子菜单入口（改图、生图、视频、特效）
  - 未登录时仍触发登录引导横幅（保持现有行为）
- **全屏抽屉**：
  - 从左侧滑入，覆盖整个屏幕（类似现有的 `MobileHistoryDrawer` 动画效果）
  - 内容区域展示四个功能卡片，每个卡片包含图标 + 名称 + 简短描述
  - 点击"改图"关闭抽屉并进入当前工作室
  - 点击其他三个菜单项关闭抽屉并显示"即将上线"占位界面

### 2.4 移动端 chat 模式聊天侧栏入口迁移

- **原入口**：左上角菜单按钮（`MobileFloatingTopBar` 的 `mobile-floating-menu`），通过 `onMenu` -> `setChatSidebarOpen(true)` 打开 `ChatHistorySidebar`
- **新入口**：在 chat 模式下的 `MobileChatMode` 内部、`MobileScreenHead` 区域左侧内嵌一个会话历史按钮
  - 按钮样式：与现有 `chat-mobile-menu`（`ChatMode` 中已定义）保持一致，使用 `Menu` 图标
  - 点击后打开原有的 `ChatHistorySidebar` 抽屉（`chatSidebarOpen` / `setChatSidebarOpen` 逻辑不变）
  - `ChatMode` 组件的 `hideMobileMenu` prop 仍保持 `true`（由 `MobileChatMode` 传入），避免 ChatMode 内部重复渲染菜单按钮
  - 由 `MobileChatMode` 在 `MobileScreenHead` 的 `leftAction` 或 `rightAction` 位置自行渲染一个按钮，调用 `setChatSidebarOpen(true)`

### 2.5 历史模块迁移至用户中心

- **原入口**：左上角菜单按钮在 config 模式下打开 `MobileHistoryDrawer`（左滑抽屉）
- **新入口**：在用户中心（`MobileProfilePage`）overview 页面的 `mobile-profile-list` 列表中，在"编辑资料"按钮**上方**添加"生成历史"按钮
  - "生成历史"按钮样式与"编辑资料"、"绑定手机号"等 `mobile-profile-row` 按钮保持一致
  - 点击后进入一个新的子页面（类似编辑资料的 profile 子页面，带返回按钮），展示历史记录列表
  - 子页面内使用现有的 `MobileHistorySheet` 内容逻辑（历史记录列表、选中、删除）

### 2.6 "即将上线"占位页面

- PC端和移动端通用
- 居中显示"即将上线"文字
- 使用 `--muted` 颜色，字体使用 `--font-mono`
- 可选：添加一个返回按钮或自动返回机制（不做强要求，由实现时决定）

## 3. 技术实现思路

### 3.1 整体策略

- 新增一个全局状态 `activeMenu`（类型：`"edit" | "generate" | "video" | "effect"`）来管理当前激活的菜单项
- PC端和移动端共享该状态，通过不同的渲染逻辑响应
- "即将上线"占位内容作为条件渲染的简单组件，无需独立路由

### 3.2 PC端菜单组件

- 在 `car-mod-studio.tsx` 的 `studio-card` 容器内、`<header>` 之前，新增一个悬浮菜单组件
- 使用纯 CSS 实现竖排 Tabs 样式（参考 `demo/meum.txt`），不依赖 shadcn/ui 的 Tabs 组件（项目中未安装该组件）
- 通过 `TooltipProvider` + `Tooltip` 实现悬停文字提示（需确认是否已安装 shadcn/ui 的 Tooltip 组件；若未安装，则用纯 CSS `::after` 伪元素实现）
- 菜单使用 `position: fixed`，定位于视口左上角，`z-index` 高于 `studio-header`

### 3.3 移动端全屏抽屉

- 在 `mobile-studio-app.tsx` 中新增 `MobileMenuDrawer` 组件
- 复用现有的 `AnimatePresence` + `motion.aside` 模式（与 `MobileHistoryDrawer` 一致）
- 抽屉内容为四个功能卡片的网格布局（2x2 或纵向列表）

### 3.4 移动端 chat 模式聊天侧栏入口

- `MobileChatMode` 组件（第 3176 行）接收 `chatSidebarOpen` 和 `setChatSidebarOpen` props
- `MobileScreenHead` 组件（第 3287 行）已有 `rightAction` prop，可新增 `leftAction` prop 或直接在 `MobileChatMode` 内部于 `MobileScreenHead` 前后渲染按钮
- 按钮点击调用 `setChatSidebarOpen(true)`，`ChatMode` 内部的 `ChatHistorySidebar`（通过 `mobileOpen={mobileSidebarOpen}` 控制显示）照常工作
- 由于 `MobileChatMode` 向 `ChatMode` 传入了 `hideMobileMenu`，需确保 ChatMode 内部的 `chat-mobile-menu` 按钮不渲染，避免两个入口并存

### 3.5 移动端用户中心历史子页面

- 在 `MobileProfileSection` 类型中新增 `"history"` 选项
- 在 `MobileProfilePage` 的 `renderEditor()` 函数中新增 `section === "history"` 分支
- 复用现有的历史记录数据获取逻辑（`props.syncHistory`、`props.historyJobs`）
- 页面结构与现有的 profile/phone 子页面保持一致：顶部返回按钮 + 标题 + 内容列表

### 3.6 与现有模块的交互

- `activeMenu` 状态变化时：
  - 若切换到"edit"，正常显示当前工作室
  - 若切换到其他三个菜单项，隐藏工作室内容，显示占位页面
- PC端头部标题区域可保持不变（"ModCar AI"），或可选地在菜单激活非"改图"时更新标题
- 移动端模式切换栏（config/chat）仅在"改图"菜单激活时显示
- `chatSidebarOpen` 状态仅在 chat 模式且 `MobileChatMode` 内部触发，与菜单抽屉互不冲突

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| PC端悬浮菜单遮挡工作室内容 | 中 | 低 | 菜单仅占左侧窄条（约48px宽），工作室内容区域适当左移或保持不变 |
| 状态管理复杂度增加（activeMenu 贯穿 PC/移动端） | 低 | 中 | 将 activeMenu 作为顶层状态，通过 props 传递，避免引入额外状态管理库 |
| 移动端左上角按钮行为变更导致用户习惯断裂 | 中 | 中 | 新的菜单抽屉提供"改图"快捷入口，减少操作步骤；历史迁移至用户中心符合常规 App 习惯 |
| demo/meum.txt 使用了 shadcn/ui Tabs + Tooltip，但项目未安装 | 高 | 中 | 用纯 CSS 实现竖排导航样式，Tooltip 用 CSS `::after` 或 title 属性替代 |
| chat 模式下内嵌侧栏按钮与 MobileScreenHead 布局冲突 | 低 | 低 | MobileScreenHead 已有 rightAction prop，可扩展支持 leftAction 或在 MobileChatMode 中自行布局 |
