# 网站接入微信登录（ModCar AI / car-edit）

> 适用项目：`ModCar AI`（Next.js 14 App Router + React 18 + TypeScript + SQLite + shadcn/ui）。
> 目标：按本方案落地后，你**只需在 `.env.local` 中填入微信开放平台下发的 `APPID` / `APPSECRET` 与回调地址**，即可完整跑通网站微信登录（扫码或快捷登录），首次登录自动建号、再次登录自动识别同一用户。

---

## 1. 方案概述

微信「网站应用」登录基于 **OAuth 2.0 授权码模式（authorization_code）**，整体时序如下：

```
浏览器/弹窗              你的后端(Next.js)              微信开放平台
    |                          |                            |
    |-- 打开 /api/auth/        |                            |
    |   wechat/login  -------->| 生成 state，种 cookie      |
    |                          |-- 302 跳转到 qrconnect --->|
    |<-------------------------|                            |
    |  重定向到微信授权页       |                            |
    |  用户扫码/确认授权        |                            |
    |                          |<--- 微信回调 redirect_uri --|
    |                          |     ?code=CODE&state=STATE |
    |                          |  校验 state                |
    |                          |  code + appid + secret     |
    |                          |------> 换取 access_token -->|
    |                          |<------ openid/unionid ------|
    |                          |  查/建本地用户(users+        |
    |                          |  user_identities)           |
    |                          |  种 session cookie          |
    |<--- 返回 HTML 通知 opener 并关闭弹窗 -------------------|
    |  前端收到 postMessage     |                            |
    |-- 刷新当前用户 / 关闭弹窗 ->|                            |
```

**关键信息：**

- 授权地址：`https://open.weixin.qq.com/connect/qrconnect`
- 换 token 地址：`https://api.weixin.qq.com/sns/oauth2/access_token`
- 拉用户信息：`https://api.weixin.qq.com/sns/userinfo`
- scope 固定为 `snsapi_login`（网站应用仅此一种）。
- `code` 有效期 **10 分钟**，且**只能换一次** access_token；`state` 用于防 CSRF。
- 换 token 成功返回 `access_token / expires_in / refresh_token / openid / unionid`（unionid 仅在账号已绑定同主体公众号/小程序或网站应用已开通时返回）。

## 2. 前置条件（来自微信开放平台，需你自行准备）

1. 注册 [微信开放平台](https://open.weixin.qq.com/) 开发者账号。
2. 创建 **网站应用**，通过审核，获得：
   - **AppID**（应用唯一标识）
   - **AppSecret**（应用密钥，**绝不可下发给前端**）
3. 在「网站应用 → 授权回调域名」中填写**回调域名**（只填域名，不带 `http://` 和路径，且必须已完成 ICP 备案）。
   - 例如你的站点部署在 `https://oncar.example.com`，则填 `oncar.example.com`；`redirect_uri` 必须是该域名下的某个路径，本方案用 `/api/auth/wechat/callback`。
4. **本地开发注意**：微信要求 `redirect_uri` 的域名等于后台配置的授权域名，且生产必须 HTTPS。`127.0.0.1` 无法作为授权域名，本地联调请用公网 HTTPS 隧道（如 cloudflared / ngrok）把 `localhost:3000` 暴露成域名，并把该域名同时配成授权域名与 `WECHAT_REDIRECT_URI`。

在项目根目录创建（或编辑）`.env.local`：

## 5. 步骤二：服务端新增 `loginOrCreateWithWechat`

在 `lib/server/db.ts` 中（`loginOrBindMockWechat` 附近）新增以下函数。它复用了已有的 `user_identities` 表与建号习惯（用户名 `wx_xxx`、默认头像、free 套餐），并优先用 `unionid` 作为跨应用唯一标识。

```ts
// lib/server/db.ts  （在文件末尾 export 区域附近新增）
export function loginOrCreateWithWechat(input: {
  openid: string
  unionid?: string
  nickname?: string
  avatarUrl?: string
}): AuthUser {
  const providerUserId = (input.unionid || input.openid).trim()
  if (!providerUserId) throw new Error("微信授权信息缺失（openid/unionid 为空）")
  // 1) 已绑定过：直接返回并刷新登录时间
  const existing = database()
    .prepare(
      "SELECT users.* FROM user_identities JOIN users ON users.id = user_identities.user_id WHERE provider = 'wechat' AND provider_user_id = ? LIMIT 1",
    )
    .get(providerUserId) as Row | undefined
  if (existing) {
    assertUserActive(existing)
    const now = nowMs()
    database().prepare("UPDATE users SET last_login_at = ?, updated_at = ? WHERE id = ?").run(now, now, String(existing.id))
    return mapAuthUser(existing)
  }
  // 2) 首次登录：自动建号并绑定
  const now = nowMs()
  const userId = `user_${crypto.randomUUID().slice(0, 8)}`
  const username = `wx_${providerUserId.slice(0, 8)}`
  database()
    .prepare(
      "INSERT INTO users (id, username, phone, password_hash, name, email, avatar_id, role, plan, status, last_login_at, updated_at, created_at) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
    )
    .run(userId, username, "", "", input.nickname?.trim() || "微信用户", `${username}@local`, DEFAULT_AVATAR_ID, "user", "free", "active", now, now, now)
  database()
    .prepare("INSERT INTO user_identities (id, user_id, provider, provider_user_id, created_at) VALUES (?, ?, ?, ?, ?)")
    .run(`ident_${crypto.randomUUID().slice(0, 8)}`, userId, "wechat", providerUserId, now)
  createAccountMessage({
    id: `${userId}-welcome-v1`,
    userId,
    kind: "system",
    title: "欢迎使用 ModCar AI",
    body: "你已通过微信登录。可在「账号设置」中绑定手机号或设置密码，以便使用更多登录方式。",
    metadata: { source: "wechat" },
    createdAt: now,
  })
  writeAudit(userId, "auth.wechat.login", { openid: input.openid, unionid: input.unionid || "" })
  return getUserById(userId) as AuthUser
}
```

> 说明：`users` 表的 `avatar_id` 指向 `avatar_presets`，因此微信头像 URL 不直接落库（避免风格不一致）。如需保留微信头像，可在 `users` 表扩展 `external_avatar_url` 列并由 `mapAuthUser` 优先返回——属可选增强，不影响登录跑通。

## 6. 步骤三：服务端新增 OAuth 路由

### 6.1 发起授权 — `app/api/auth/wechat/login/route.ts`

```ts
import { NextResponse } from "next/server"
import { randomBytes } from "crypto"

export const runtime = "nodejs"
export const dynamic = "force-dynamic"

export async function GET() {
  const appid = process.env.WECHAT_APPID
  const redirectUri = process.env.WECHAT_REDIRECT_URI
  if (!appid || !redirectUri) {
    // 未配置时直接在弹窗内 alert 提示，满足“未配置直接弹窗提示”要求
    return configMissingPage(
      "微信登录未配置：服务端缺少 WECHAT_APPID 或 WECHAT_REDIRECT_URI，请在 .env.local 中填写后重启服务。",
    )
  }
  const state = randomBytes(16).toString("hex")
  const url = new URL("https://open.weixin.qq.com/connect/qrconnect")
  url.searchParams.set("appid", appid)
  url.searchParams.set("redirect_uri", redirectUri) // 后端做 encode，配合微信要求
  url.searchParams.set("response_type", "code")
  url.searchParams.set("scope", "snsapi_login")
  url.searchParams.set("state", state)

  const res = NextResponse.redirect(url.toString())
  res.cookies.set("wx_oauth_state", state, {
    httpOnly: true,
    sameSite: "lax",
    secure: process.env.NODE_ENV === "production",
    path: "/",
    maxAge: 600, // 10 分钟，足够完成扫码
  })
  return res
}
```

> 前端会以 `window.open('/api/auth/wechat/login', ...)` 打开弹窗，弹窗被 302 带到微信授权页。
> **未配置直接弹窗提示**：`login` 与 `callback` 路由在缺少 `WECHAT_APPID` / `WECHAT_APPSECRET` / `WECHAT_REDIRECT_URI` 时，不再返回 JSON，而是返回一段 HTML，在弹窗内 `window.alert(...)` 直接提示“微信登录未配置”，并通过 `postMessage` 通知父窗口后关闭。前端 `auth-modal.tsx` 的「微信登录」按钮也会先判断 `process.env.NEXT_PUBLIC_WECHAT_APPID`：若为空，点击即 `window.alert(...)` 提示，避免无意义的弹窗。

### 6.2 处理回调 — `app/api/auth/wechat/callback/route.ts`

```ts
import { NextRequest, NextResponse } from "next/server"
import { loginOrCreateWithWechat } from "@/lib/server/db"
import { attachSession } from "@/lib/server/auth"

export const runtime = "nodejs"
export const dynamic = "force-dynamic"

export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url)
  const code = searchParams.get("code")
  const state = searchParams.get("state")
  const savedState = request.cookies.get("wx_oauth_state")?.value

  if (!code || !state || !savedState || state !== savedState) {
    return htmlResult(false, "state 校验失败或缺少 code，请重试。")
  }

  try {
    const appid = process.env.WECHAT_APPID
    const secret = process.env.WECHAT_APPSECRET
    if (!appid || !secret) throw new Error("微信登录未配置（缺少 WECHAT_APPSECRET）。")

    // 1) code 换 access_token
    const tokenRes = await fetch(
      `https://api.weixin.qq.com/sns/oauth2/access_token?appid=${appid}&secret=${secret}&code=${code}&grant_type=authorization_code`,
    )
    const token = await tokenRes.json()
    if (token.errcode) throw new Error(`微信换 token 失败: ${token.errcode} ${token.errmsg}`)
    const { access_token, openid, unionid } = token

    // 2) 拉用户昵称/头像（可选，失败不影响登录）
    let nickname = ""
    let avatarUrl = ""
    try {
      const infoRes = await fetch(
        `https://api.weixin.qq.com/sns/userinfo?access_token=${access_token}&openid=${openid}&lang=zh_CN`,
      )
      const info = await infoRes.json()
      if (!info.errcode) {
        nickname = info.nickname || ""
        avatarUrl = info.headimgurl || ""
      }
    } catch {
      /* 忽略用户信息拉取失败 */
    }

    // 3) 查/建本地用户并种会话
    const user = loginOrCreateWithWechat({ openid, unionid, nickname, avatarUrl })
    const res = htmlResult(true)
    attachSession(res, user.id) // 写入 car_mod_session cookie
    res.cookies.set("wx_oauth_state", "", { path: "/", maxAge: 0 })
    return res
  } catch (err) {
    return htmlResult(false, err instanceof Error ? err.message : "微信登录失败。")
  }
}

// 返回极简 HTML：通知 opener 并关闭弹窗（同时作为无 opener 时的兜底提示）
function htmlResult(ok: boolean, message = "") {
  const script = `
    <script>
      (function () {
        try {
          if (window.opener) {
            window.opener.postMessage({ type: "wechat-login", ok: ${ok}, message: ${JSON.stringify(message)} }, "*");
          }
        } catch (e) {}
        setTimeout(function () { window.close(); }, 400);
      })();
    </script>`
  const body = ok
    ? "<p>微信登录成功，正在关闭窗口…</p>"
    : `<p>微信登录失败：${message}</p>`
  return new NextResponse(`<!doctype html><html><head><meta charset="utf-8"><title>微信登录</title></head><body>${body}${script}</body></html>`, {
    status: 200,
    headers: { "Content-Type": "text/html; charset=utf-8" },
  })
}
```

## 7. 步骤四：前端「微信登录」按钮（auth-modal.tsx）

在登录区（现有手机号/密码入口附近）增加一个微信入口。下面给出可挂接的按钮与处理逻辑；具体落点可放在 `MobileStep` 的 `oneTap` / `password` 视图内，或作为独立一行「第三方登录」分隔区。

```tsx
// components/auth-modal.tsx （示意：放在登录表单下方）
import { MessageCircle } from "lucide-react" // 项目已用 lucide-react

function AuthModal(props: { onSuccess?: () => void; refreshUser?: () => void; onClose?: () => void }) {
  const openWechatLogin = () => {
    const popup = window.open(
      "/api/auth/wechat/login",
      "wechat-login",
      "width=420,height=560",
    )
    const onMsg = (e: MessageEvent) => {
      if (e.data?.type !== "wechat-login") return
      window.removeEventListener("message", onMsg)
      popup?.close()
      if (e.data.ok) {
        props.refreshUser?.()      // 重新拉取 /api/auth/me，刷新当前用户
        props.onSuccess?.()
        props.onClose?.()
      } else {
        alert(e.data.message || "微信登录失败，请重试。")
      }
    }
    window.addEventListener("message", onMsg)
  }

  return (
    <div>
      {/* ……已有登录表单…… */}

      <div className="wechat-login-row">
        <button type="button" onClick={openWechatLogin} className="wechat-login-btn">
          <MessageCircle size={18} />
          微信扫码登录
        </button>
      </div>
    </div>
  )
}
```

> `refreshUser` 应与密码登录成功后的刷新逻辑一致（本项目通常是一个重新请求 `/api/auth/me` 并写入全局状态的回调）。如你的 modal 已有「登录成功后回调」，直接复用即可。

### （可选进阶）内嵌二维码到弹窗内

若不希望弹新窗口，可用微信官方 JS 在 modal 内直接渲染二维码（需 `NEXT_PUBLIC_WECHAT_APPID` 与可嵌入的 `redirect_uri`）。在页面引入：

```html
<script src="https://res.wx.qq.com/connect/zh_CN/htmledition/js/wxLogin.js"></script>
```

```ts
useEffect(() => {
  if (!containerRef.current || !process.env.NEXT_PUBLIC_WECHAT_APPID) return
  // @ts-ignore 微信全局对象
  new window.WxLogin({
    self_redirect: false,
    id: "wechat-qr",
    appid: process.env.NEXT_PUBLIC_WECHAT_APPID,
    scope: "snsapi_login",
    redirect_uri: encodeURIComponent(process.env.NEXT_PUBLIC_WECHAT_REDIRECT_URI || ""),
    state: Math.random().toString(36).slice(2),
    style: "black",
  })
}, [])
```

> 内嵌模式下，扫码确认后浏览器会**跳转到 `redirect_uri`**（即 `callback` 路由）。若 `self_redirect:false`，跳转发生在 top window，此时 `callback` 返回的前端 `postMessage` 无法到达 opener（已无弹窗）。
> 因此内嵌方案需改用「`callback` 渲染一个挂在你站点域名下的 HTML 页，该页读取 `code` 后再 `postMessage` 给父窗口」的二次转发；或干脆让内嵌二维码的 `redirect_uri` 指向一个独立页面完成登录后前端路由回 modal。生产落地建议优先采用**第 6 节的弹窗跳转方案**（更简单、最稳）。

## 8. 安全要点（务必遵守）

- **AppSecret 只在服务端使用**：仅出现在 `callback` 路由与 `.env.local`，绝不进前端、不进 `NEXT_PUBLIC_*`、不进仓库。
- **state 防 CSRF**：`login` 路由生成随机 `state` 写入 `httpOnly` cookie，`callback` 校验一致后才继续；不一致直接拒绝。
- **code 一次性 & 短时效**：微信 `code` 10 分钟过期且只能用一次，天然防重放；本方案不在本地持久化 code。
- **HTTPS**：生产必须 HTTPS。`attachSession` 的 `secure` 已按 `NEXT_PUBLIC_APP_URL`/部署环境自动开启，无需额外处理。
- **unionid 作为主标识**：当开放平台返回 `unionid` 时，用它做 `provider_user_id`，可保证同一微信用户在你同主体的公众号/小程序/网站应用间身份一致；仅用 `openid` 也能跑通，但跨应用不互通。
- **限流与审计**：建号/登录已通过 `writeAudit` 留痕；如担心被刷，可在 `login`/`callback` 叠加 IP 限流（复用项目已有的 `assertVerificationRateLimit` 思路）。

## 10. 常见问题

| 现象 | 原因 / 解决办法 |
|---|---|
| 微信提示「该链接无法访问」 | `redirect_uri` 域名与后台**授权回调域名**不一致；或 `scope` 不是 `snsapi_login`。确认 `WECHAT_REDIRECT_URI` 的域名已配置且未带协议头。 |
| 本地开发 302 后微信报域名不符 | 微信不接受 `127.0.0.1` 作为授权域名。用公网 HTTPS 隧道映射本地 3000 端口，并把隧道域名配成授权域名与 `WECHAT_REDIRECT_URI`。 |
| 拿不到 `unionid` | 网站应用需在开放平台绑定同主体公众号/小程序，或已开通 unionid 能力；未开通时只用 `openid` 登录（同一网站应用内仍能识别，但跨应用不互通）。 |
| 扫码后弹窗不关闭 / 未登录 | 检查 `callback` 是否被反向代理剥离了 cookie（同站即可）；以及前端 `message` 监听是否在弹窗关闭前已注册。 |
| 生产环境 cookie 不生效 | 确认站点为 HTTPS；`attachSession` 会自动设 `secure`，若反向代理终止 TLS 导致 `NEXT_PUBLIC_APP_URL` 仍为 http，可显式设 `AUTH_COOKIE_SECURE=1`。 |
